# Get-On UI Specification - Custom domains

This file contains Sections 7 and 8 of the custom domains brief verbatim. For the Address settings page this file replaces the earlier Address spec.

## 7. Domains UI specification (atom level)
Tokens and components come from `docs/ui-spec.md` and `docs/ui-spec-app.md` (AppPage, PageHeader, Card, Button, Input, Select, Badge, Dialog, Menu, Toast, InfoBox, segmented control, switch row, progress bar, ListRow, SettingsSection, ConfirmDialog, EmptyState, skeletons, copy buttons). Monospace stack for record values: `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`, 13/1.5 in lists and 14/1.5 in cards.

### 7.1 Shared domain components
- **`DomainStatus` badge** (height 24, padding 0 10, radius 999, 12/700): `draft` neutral "Not finished"; `awaiting_txt` warning soft with clock icon "Waiting for verification"; `verified` info soft "Verified"; `connecting` info soft with a 12 px spinner "Connecting"; `live` success soft with an 8 px dot "Live"; `attention` warning soft with alert icon "Needs attention"; `stalled` neutral "Not connected yet"; `plan_lapsed` accent soft with pause icon "Paused"; `unassigned` neutral "Not used by a website"; `removing` neutral "Removing"; `removed` and `failed` danger soft "Removed" and "Could not connect". A `compact` variant shows only the dot or icon. A **`HostnameStatus` chip** (same size) uses: `pending` warning soft "Waiting for the connection record"; `preparing` info soft "Preparing"; `ready_to_switch` success soft "Ready to switch"; `active` info soft "Almost live"; `live` success "Live"; `moved` warning "Record changed"; `blocked` danger "Blocked"; `error` danger "Problem".
- **Role chips:** "Main address" (primary soft, star icon 12), "Also redirects" (neutral, corner-up-right icon 12).
- **`CopyValue`:** row (height 44, radius 12, bg `--surface-muted`, 1px `--border`, padding 0 4 0 14, flex gap 8) with the value (monospace 14, truncated, `title`) and a "Copy" ghost icon button 36x36 (copy icon; success check icon for 1.5 seconds and toast "Copied."). A labelled variant stacks a 12/700 caps label above.
- **`RecordCard`** (the "records to add" component, reusable later for email records): Card (padding 16, radius 16, 1px `--border`) with a top row: type chip (height 24, padding 0 10, radius 8, 12/700, `--surface-muted`: "TXT" or "CNAME"), title 15/600 ("Prove you own example.com", "Connect www.example.com"), status chip at the right (see below). Body rows (label 12/700 caps muted over a `CopyValue`): **Type**, **Name** (relative name such as `_geton-verify` or `www`, and under it a muted 12 line "Some providers want the full name: _geton-verify.example.com" with its own Copy), **Value**, and a plain **Remember for** line "Use Automatic, or 5 minutes if asked" (13 muted). A footer line (13 muted) with the last check time and a "Check now" ghost sm button (cooldown with countdown). **Record status chips:** "Not found yet" (warning soft, clock), "Wrong value" (danger soft, alert), "Found" (success soft, check), "Optional" (neutral), "Not needed now" (neutral). Locked-down copy: values are never editable.
- **`HelpTip`:** 18 px info icon button (44x44 hit area) opening a popover (width 280, padding 12, radius 12, 14/1.5) used for "DNS settings", "TXT record", "CNAME record", "Bare domain", "Spreading".
- **Stepper** (vertical): rows with a 28 px circle (done: filled `--success` with check; current: 2px `--primary` ring with 14 px spinner; waiting: 2px `--border-strong` ring; problem: filled `--warning-soft` with alert icon), title 15/600, helper 14 muted, time 12 muted, 2px connector (done segments `--success`), row gap 20.

### 7.2 Address settings page (`settings/address`, replaces the earlier spec)
Head: "Address", description "Where people find your website." Cards:
1. **Free address** (padding 20): caption 12/700 caps "Your free address"; address 20/700 `--primary` (break-all) with Copy, Open (disabled until live), Share and QR buttons (secondary sm). When a main address is live: switch row "Send visitors from this address to {main address}" (default on; helper "Visitors and Google go to your own address. This address keeps working as a redirect."). Line 14 muted "This address is free and comes with your plan."
2. **Your domains** (title 17/600 with usage "{n} of {limit}" muted):
   - Free plan: upgrade card (dashed 2px `--border-strong`, radius 16, padding 24): globe icon tile 48 (`--accent-soft`), H3 "Use your own domain", text "Use an address like www.yourbusiness.com instead of {free address}. Included from the Basic plan.", three benefits with check icons ("Your own name", "Secure padlock included", "We guide you step by step"), "See plans" primary md.
   - Paid plan, none yet: the same card without the plan note and with "Connect a domain" primary lg.
   - **Domain cards** (gap 12): Card padding 20, radius 16: globe icon tile 40, display name 17/600 (punycode in 12 muted when different), `DomainStatus`, role chip; below it the address rows (each hostname in monospace 14 with `HostnameStatus` and "Main address" or "Also redirects" chips); a status line 13 muted ("Waiting for you to add the verification record", "Waiting for the connection record", "Live since {date}", "Needs attention: {plain reason}"); right "Manage" primary sm and kebab (Make main address, Open website (live), Disconnect, Remove). Below 640 the buttons stack. Attention cards get a 4px left border `--warning-text`.
   - At the limit: InfoBox warning "Your {Plan} plan includes {n} domain{s} for each website." with "See plans"; "Connect a domain" disabled with that tooltip.
   - Paused (plan lapsed): InfoBox accent "Your domain is paused because your plan no longer includes it." with "See plans".
3. **Buy a domain** (muted dashed card): icon tile 48, title "Buy a domain" with a "Coming soon" pill, text "Soon you will be able to buy and connect a domain here."
4. The QR dialog and Share menu use the main address.

### 7.3 Connect wizard (`settings/address/connect`, full page, AppPage width `narrow` 720)
Header: back link "Address" (arrow-left, 14/600 `--primary`, height 44), H1 (28) "Connect your domain", step indicator (four items: dots 8 px, current 24x8 pill `--primary`, done `--success`; label "Step {n} of 4: {name}" 13 muted). Content Card (padding 24, 32 from 640, radius 24). Action bar: below 768 fixed at the bottom (height 72 plus safe area, bg `--surface`, top border, padding 12 20, "Back" ghost md and the primary lg); from 768 inline below the card (margin-top 24). State is saved on the server (the draft); returning resumes at the right step from the domain status. A ghost link "Cancel and delete this draft" (14, danger text) appears on steps 2 to 4 with a ConfirmDialog (never deletes a live domain).
**Step 1, "Your domain".** H2 (22) "What is your domain?" text 15 muted "Enter the domain you own, like example.com. You can also enter an address like shop.example.com." Input lg (height 56, font 18, autofocus, inputmode url, autocapitalize off, placeholder "yourbusiness.com"). A live normalisation chip under it (radius 999, bg `--surface-muted`, 13): "We will use the domain: example.com" (Unicode shows both forms; a subdomain input adds "and suggest the address shop.example.com on the next step"). Continue runs the lookup (button loading "Checking..."), then shows a **result card** (bg `--surface-muted`, radius 16, padding 16, rows 14): "Registered with {registrar}", "Expires {date}" (warning chip under 30 days), "Your DNS settings are with {provider hint}" (with HelpTip "DNS settings are where you add records. They are kept by the company your nameservers point to, which is not always the company you bought the domain from."), and a green "Looks good" row. InfoBoxes appear for: already connected by another team to the same address later (handled at step 2); the domain is on Cloudflare DNS (info, hint about DNS only records); CAA records found (warning, "Your domain limits who can issue padlocks. We will show you what to add."); needs review (info); plan, limit and daily limit errors (warning with "See plans"); blocked (danger). Primary "Continue" is enabled when the lookup finishes without blocking errors.
**Step 2, "Choose your address".** H2 "Which address should open your website?" Radio cards (stacked, min-height 88, padding 16, radius 16, 1.5px `--border-strong`; selected 2px `--primary` and `--primary-soft`; radio 22 at the left): (1) "www.example.com" with the "Recommended" accent chip and helper "Works with every domain provider."; (2) "example.com" helper "No www. Your provider must allow an ALIAS, ANAME or CNAME at the bare domain. If it does not, choose www." with a HelpTip "Bare domain"; (3) "A different name" with an Input revealing "shop" + suffix ".example.com" (label "Name", validated per 5.2, prefilled from a subdomain input). Under the radios a switch row (hidden for choice 3): "Also connect {the other form} and send visitors to {main}" (default on for choice 1; off for choice 2; helper "People who type {the other form} still arrive.") and the line "You can change this later." If an address is already connected elsewhere show `HOSTNAME_TAKEN` as a danger InfoBox with the two buttons from 6.7. If the lookup shows an existing website at the chosen address show an InfoBox accent: "This address already shows another website. You can connect without any break in service." and a radio group "How do you want to switch?" ("Prepare first (recommended)", "Switch now. Visitors may see an error for a few minutes."). Continue is disabled until the choices are valid.
**Step 3, "Prove it is yours" (TXT).** H2 "First, prove you own {domain}" text 15/1.6 "Add this record in your DNS settings. It is a short note that only the owner of the domain can add." The **`RecordCard`** for the TXT (Type TXT; Name `_geton-verify`; Value `geton-verify={hex}`; Remember for "Automatic"). Below it a **"How to add it" panel** (card, padding 16, bg `--surface-muted`, radius 16): title "Where do I add this?" and numbered steps (15/1.6; step numbers in 24 px circles `--primary-soft`): "1. Log in to {provider hint or 'the company that manages your domain'}." "2. Open the DNS settings (they may be called DNS records, DNS zone or Advanced DNS)." "3. Add a new record and choose type TXT." "4. Paste the name and the value above. If your provider adds your domain to the name automatically, use only `_geton-verify`." "5. Save." plus the note "Menu names can look a little different." InfoBoxes: info "It can take a few minutes, sometimes up to an hour, to show up."; if wrong value found: danger "We found a record, but the value is different. Copy the value again."; if the checked record was already tried: neutral "If you checked before adding it, it can take up to 30 minutes to show up." Button "Check now" (primary md in the card; the wizard auto-polls every 20 seconds for 10 minutes with a live status line "Checking... last checked {time}" and an `aria-live` announcement). Primary "Continue" (enabled when verified) and a ghost "I will do this later" saving the draft. A verified state shows a success row (check-circle `--success`, "Domain verified").
**Step 4, "Connect your website" (CNAME).** H2 "Now connect {main address}" text 15/1.6 "Add this record so your address points to your Get-On website." One **`RecordCard`** per chosen address (Type CNAME; Name `www` or `@` or `shop`; Value the connection target from the server; Remember for "Automatic"). Warnings per card: for `@` an InfoBox info "Some providers call this an ALIAS or ANAME record. If your provider does not allow it, connect www instead and forward {bare domain} to www in your provider's forwarding settings." and a "Use www instead" ghost sm button; for any address with existing A, AAAA or CNAME answers: InfoBox warning "Delete the old record first. A name can have only one connection record." listing the found records read-only (type and value); If the lookup found CAA records: InfoBox warning listing the exact CAA records to add (from the spike's verified authority list) as `RecordCard`s with status "Optional" and the text "Your domain only lets some companies issue padlocks. Add these so yours can be issued."; If the DNS is on Cloudflare: InfoBox info per the spike finding (for example "Use DNS only, not proxied, for this record." when verified). **Prepare-first mode** shows, above the CNAME cards, two more `RecordCard`s per address labelled "Optional now: prepare without interruption" (the provider's ownership TXT and validation TXT, names and values from the provider), a Stepper "Prepare, check, switch" and the CNAME cards **disabled with the text "Wait until we say it is ready"** until the hostname reaches `ready_to_switch`; then they enable and the page says "Ready! Now change your connection record." Under the cards: the live **Stepper** (below) and buttons "Check now" (secondary md, cooldown) and "Close and come back later" (ghost md).
**Waiting and success (also the domain Overview).** Stepper rows (per main address): "Verification record found" (done after Step 3), "Connection record found" (waiting), "Secure padlock (HTTPS) ready" (waiting; helper "Usually a few minutes after your record is found."), "Website connected" (waiting). A switch row "Email me when it is ready" (default on). When live, the card swaps to the **success view**: 72 circle `--success-soft` with check 36, H2 "Your website is live on {main address}!", text "It may take a minute to show everywhere.", `CopyValue` of the address, buttons "Open my website" (primary lg, external-link), "Share" and "QR code" (secondary md), then "What to do next" rows: "Publish to update your search results" with `PublishButton` (or "We updated your website for you" after auto-publish), "Add your address to Google Search Console" (link), "You can delete the verification record now if you like. Keeping it is fine." (info row).

### 7.4 Domain detail (`settings/address/domains/[domainId]`)
Head: back link "Address" (below 1024) or breadcrumb "Address / {domain}", H2 (22) with the display name, `DomainStatus`, and a kebab (Make main address, Open website, Disconnect, Remove). Underline tabs (height 48): **Overview**, **Settings**, **Activity** (horizontally scrollable with a 24 px fade, `aria-current`).
**Overview**
- **Status banner** (Card padding 20, 4px left border by state): icon tile 40, title 17/600, text 14/1.5:
  - `draft` or `awaiting_txt`: "Prove you own {domain}" with the TXT `RecordCard` and "Check now", plus "Continue setup".
  - `verified` (no hostnames): "Choose how people reach your website" with "Choose an address" primary md (opens wizard step 2).
  - `connecting`: "Waiting for your connection record" with the CNAME `RecordCard`s and the Stepper.
  - `live`: "Your website is live on {main address}" with `CopyValue`, Open, Share and QR buttons.
  - `attention`: the plain reason ("The connection record was removed or changed. Please set it back to the value below so your website works.", "Your secure padlock could not be renewed. We are looking into it.", "We cannot reach your website on this address right now. We will keep checking.", "This address was blocked. Please contact us.") plus the relevant `RecordCard` and "Check now" and "Contact support".
  - `stalled`: "Still waiting for your connection record" with the records and "Contact support".
  - `plan_lapsed`: accent InfoBox "This domain is paused" with "See plans".
  - `unassigned`: "Not used by a website" with "Use it for {website name}" primary md.
- **"Your records" card** (padding 20): title 17/600 and text 14 muted "These are the records that connect {domain}. Keep the connection records in place." A list of `RecordCard`s (verification TXT with status "Found", one CNAME per address with live status, optional prepare-first and CAA records only while relevant). Each shows its last check time and "Check now". A footnote 13 muted "You can remove the verification record once your website is live, but keeping it is fine."
- **Addresses** (padding 20): rows for each hostname (min-height 64): the address (monospace 15/600), `HostnameStatus`, role chip, "Open" ghost sm (live), kebab (Make main address (live), Remove address). "Add an address" secondary md when fewer than two addresses and the domain is verified (opens a dialog: radio cards for the other form or a custom name with the same validation and prepare-first choice, then shows the new `RecordCard`).
- **Setup progress Stepper** and **Domain info** (rows "Registered with", "Expires {date}" with warning chips under 30 days and danger under 7, "Added {date}", "Verified {date}", "Last checked {time}") plus the expiry InfoBox "Your domain expires on {date}. Renew it with your registrar so your website stays online."
- **Quick actions:** "Check now" (secondary md, cooldown), "Open website" (disabled until live), "Check my domain again" (secondary md, when the verification is older than 90 days).
- **Domain checks** (collapsible card, native details "Domain checks"): runs the diagnostics (conflicting records at the same name, CNAME pointing elsewhere, CAA blocking issuers, TXT value mismatch, bare-domain CNAME unsupported hint) with success, warning and tip rows (icon, title 15/600, detail 14 muted, a "Fix it" ghost sm that scrolls to the right `RecordCard`) and a "Technical details" disclosure showing the provider's raw status codes (copyable for support).
**Settings tab**
- **Main address** (SettingsSection, radio cards listing the connected addresses with their status; only live addresses can be chosen; helper "Visitors and Google use this address. Your other addresses send visitors here."). Changing opens a ConfirmDialog (440): "Change your main address?" "Visitors and Google will move to {new}. This can take a few days to show in search results." then the toast "Publish to update your sitemap and links." with `PublishButton`.
- **Redirect from my free address** switch row (default on; helper "Visitors who use {free address} are sent to {main address}.").
- **Publish automatically when this address goes live** switch (default on; helper "We only do this if you have no unfinished changes.").
- **Secure connection (HTTPS)** read-only row with a lock icon: "Always on. Visitors are sent to the secure version automatically."
- **Other domains** (when the plan allows more than one): list of alias domains, each redirecting to the main address, with "Connect another domain" (starts the wizard with `role=alias`).
- **Danger area** (card with a 4px left border `--danger`, padding 20): "Move to another website" (secondary md; Select of the team's other websites with room, ConfirmDialog: "The old website stops using this domain."), "Disconnect from this website" (secondary md; ConfirmDialog "Disconnect {domain}? Your website will no longer open on this domain. You can connect it to another website later."), "Remove this domain from Get-On" (danger md; dialog 7.5).
**Activity tab:** list Card (padding 0) of `domain_events` with the same row design as the project Activity page (icon tile 36 by event, summary, "by {name}" or "automatically", time), filter Select ("Everything", "Setup", "Problems"), "Show more".

### 7.5 Remove domain dialog
Dialog 560 (sheet on mobile): icon tile 48 (`--danger-soft`, trash icon), H3 "Remove {domain} from Get-On?", text 15 muted "Your website will stop opening on this domain. We will also remove the connection from our side." A checklist (rows with minus-circle icons) "After this, you can delete these records at your DNS provider:" listing the CNAME records and the TXT record with `CopyValue`s of names only. Input "Type {domain} to confirm", buttons "Cancel" and "Remove domain" (danger md; loading "Removing..."). Warning InfoBox: "If you leave the connection record in place, visitors will see an error page on that address until you delete it." Success toast "{domain} was removed." with the checklist shown again on the Address page for 7 days as a dismissible InfoBox.

### 7.6 Accessibility, motion and empty states
Every status has text, never colour alone; `aria-live="polite"` on the status banner and stepper; copy buttons announce "Copied"; record cards are lists with labelled fields; dialogs trap focus; the wizard moves focus to the step heading; polling updates are announced politely and never steal focus; reduced motion removes spinner speed-ups and the success scale-in; mobile uses full-width cards and fixed action bars.

## 8. Other screens and relationships

### 8.1 Team Domains page (`/dashboard/domains`, wide container 1120)
Add "Domains" (globe icon) to the team sidebar under Workspace after Templates and to quick find; on mobile link it from the Websites page header menu and the Plan page. PageHeader: title "Domains", description "Domains connected to your websites in {team name}." Action "Connect a domain" primary md (opens a Select of websites, then the wizard). Content: Card (padding 0, overflow-x auto, min width 880): Domain (name 15/600 and role chip), Website (link or "Not used"), Addresses (count and the main address), Status (`DomainStatus`), Expires (date with warning chips), Actions (kebab: Manage, Open website, Disconnect). Empty state: dashed card, globe icon 40 in a 72 circle, H3 "No domains yet", text "Connect your own domain to a website to see it here.", button "Connect a domain". Free plan: upgrade card. Filter chips (All, Live, Needs attention, Waiting). Mobile: cards.

### 8.2 Overview, checklist, website cards, settings navigation
- Checklist item "Use your own domain" becomes active (links to the wizard; "Upgrade" pill on Free; completes when a main address is live).
- The Overview address card shows the main address with `DomainStatus` when a domain exists, and a warning dot when a domain needs attention (also on the Settings nav item "Address" and the website card).
- Website cards show the main address and a globe icon when a custom domain is live.
- Quick find adds actions "Connect a domain", "Check my domain" and "Domains".

### 8.3 Addresses everywhere
Every place that shows or copies the website address uses `primaryUrl()`. Page paths in the Pages manager stay as `/path`.

### 8.4 Sitemap and Google settings page
Add the post-connection InfoBox and the optional Domain property guidance card from 6.6; no record editing.

### 8.5 Public platform pages (Worker; same visual rules as earlier platform pages)
- **Domain not connected:** icon plug (inline SVG 40 in the 80 circle), H1 "This domain is not connected to a website yet", text "If you own this domain, log in to Get-On and choose a website for it.", button "Go to Get-On".
- **Domain paused:** icon pause, H1 "This website is taking a break", text "The owner needs to renew their plan to bring it back.", button "Go to Get-On"; status 503, `Retry-After: 3600`.
- Both `noindex`, `no-store`, never reveal the owner or website name.

### 8.6 Admin console additions (`/admin/domains`)
Add "Domains" to the admin sidebar: search by domain, hostname, owner email or website; table (Domain, Hostnames with status chips, Website, Team, Status, Reason, Verified, Expires, Actions). Row actions: "Re-check now", "Retry validation", "Approve" (review state; writes `reviewed_by_support`), "Reject" (removes the claim with an email to the team), "Reassign hostname to another team" (typed confirmation and a required note with evidence), "Pause" and "Resume", "Delete provider hostname" (typed confirmation), "Simulate plan lapse and restore" (development only). Detail view (`/admin/domains/[id]`): Overview, Hostnames (provider status, raw error codes, copyable provider ids), Events, Verification (value, started, verified). Operations page cards: total hostnames versus the included count and the maximum with a plain cost note ("About {n} hostnames beyond the included {m}. Check Cloudflare for current pricing."), pending hostnames versus `DOMAINS_MAX_PENDING_HOSTNAMES`, domains in `attention`, `stalled` and review, provider error rate and circuit state, setup check result (`checkSetup()`), the last run of every domain job. Every admin action writes `admin_audit_log` and `domain_events` marked "by support".

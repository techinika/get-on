# Get-On UI Specification - Plugins

## 8. Template registry (`packages/blocks/templates`)
```ts
type SectionTemplate = { id: string; pluginId: string; category: 'section'|'form'|'embed'; name: string; description: string; tags: string[]; build: (ctx: ProjectContext) => Block[] }
```
`ProjectContext` carries business name, type, contact details, theme, and the list of pages (to link the CTA to a page whose address contains "contact", otherwise no link). Each template returns fresh blocks with new ids. Prefill every details field from the project's settings. Twelve Contact templates (ids use the `contact.` prefix):
| Id | Category | Name | Description (shown to users) | Blocks |
|---|---|---|---|---|
| `contact.section.side-by-side` | section | Side by side | Your details on one side, the form on the other. | `contact-form` split, heading "Get in touch", background plain |
| `contact.section.details-above` | section | Details above the form | Your contact details first, then a simple form. | `contact-details` (soft) then `contact-form` classic (plain) |
| `contact.section.big-headline` | section | Big headline | A friendly welcome with a form in a box. | `hero` text-only (heading "We would love to hear from you", subheading "Tell us a little about what you need.", no button, soft) then `contact-form` boxed |
| `contact.form.classic` | form | Classic form | A simple, centred form. | `contact-form` classic |
| `contact.form.boxed` | form | Form in a box | A form inside a soft card. | `contact-form` boxed, background soft |
| `contact.form.compact` | form | Compact form | A short form with three fields. | `contact-form` compact |
| `contact.form.colourful` | form | Colourful form | A form on your brand colour. | `contact-form` classic, background brand |
| `contact.embed.footer-mini` | embed | Small footer form | A tiny form for the bottom of a page. | `contact-form` mini, background soft |
| `contact.embed.cta-strip` | embed | Call-to-action strip | A slim bar that invites people to get in touch. | `contact-cta` strip |
| `contact.embed.cta-card` | embed | Call-to-action card | A card with a short message and a button. | `contact-cta` card |
| `contact.embed.banner` | embed | Colourful banner | A bold banner on your brand colour. | `contact-cta` banner |
| `contact.embed.quick-buttons` | embed | Quick contact buttons | Call, email and WhatsApp buttons. | `quick-contact` row |
Validate each template through the block schemas and render each at the three bands in tests. Add the guard test: every `available` plugin has at least 8 templates across at least 2 categories.

"Add another email address" Input plus "Add" secondary md; helper "We will send a link to confirm it. Up to 3 extra addresses." 2. **Thank-you message.** Input "Title" (default "Thank you!", max 60), Textarea "Message" (default "Your message has been sent. We will get back to you soon.", max 300, counter). - If the plugin is Off: the Off InfoBox as above. If the site has never been published: InfoBox info "Publish your website so visitors can reach you." with the `PublishButton`.
- If `form_limit_hit_at` is within 24 hours: InfoBox warning "Your website reached today's message limit. Visitors were asked to contact you another way." with "See plans".
- Toolbar (margin-bottom 16): tab row (underline tabs, height 48) "All", "New" with count, "Archived", "Spam" (counts in 13 muted); search Input (height 44, search icon, placeholder "Search messages", debounce 300 ms, searches name, email, phone and message text).
- **Desktop (1024 and above):** one Card (padding 0, overflow hidden) with a two-pane grid `380px minmax(0,1fr)`, height `clamp(520px, calc(100dvh - 300px), 760px)`, each pane scrolling independently, a 1px `--border` divider.
  - List rows (min-height 80, padding 14 16, bottom border 1px `--border`, cursor pointer): left an 8 px dot (`--primary` when unread, hidden when read), then line 1: name 15 (700 unread, 500 read, "Someone (no name)" when empty) truncated and time 12 `--text-muted` on the right ("2h", "Yesterday", "12 Oct"); line 2: message snippet 14 `--text-muted`, two lines clamped; line 3 (only when relevant): neutral chip "From {page title}" 12 and, in the Spam tab, a danger chip "Spam". Selected row background `--primary-soft`; hover `--row-hover`. A checkbox (24x24) replaces the dot on hover and on keyboard focus for bulk actions. Bulk bar replaces the toolbar tabs when items are selected: "{n} selected" 15/600 and buttons Archive, Mark as read, Mark as spam, Delete (danger), plus "Clear".
  - Detail pane: header (padding 20 24, bottom border 1px `--border`): name 20/700 (Bricolage), email as a mailto link 15 `--primary`, phone as a tel link, line "Received {full date and time}" and "From {page title}" 13 `--text-muted`. Action row (padding 16 24, gap 8, wrap): primary md "Reply by email" (mail icon; opens `mailto:` with subject "Re: your message to {business}" and a body that quotes the first 500 characters), secondary md "Reply on WhatsApp" (message-circle icon in `#1FA855`; only when the phone parses as a valid international number, using `libphonenumber-js`; link `https://wa.me/{digits}?text=…`), secondary md "Call" (phone icon; only when a phone exists), a toggle chip "Replied" (height 40, radius 999, 1.5px border; on state `--success-soft` with check), ghost icon buttons 44x44: Archive (archive icon; becomes "Move to inbox" in Archive), Spam (shield-alert; becomes "Not spam"), Delete (trash-2, danger hover, ConfirmDialog "Delete this message?" "It cannot be undone."). Body (padding 24): a card (bg `--surface-muted`, radius 16, padding 20) with the message at 16/1.7, `white-space: pre-wrap`, `overflow-wrap: anywhere`; links are shown as plain text, never auto-linked. Opening a new message marks it read after 1.5 seconds (optimistic). Empty detail (nothing selected): centred inbox icon 40 and "Choose a message to read it."
- **Mobile and tablet (below 1024):** the list fills the width inside the page (rows as above, full width, no card border radius inside edge padding); tapping a row opens `.../messages/[messageId]` as its own page with a back link "Messages", the detail layout stacked (header, action buttons wrap 2 per row, message card), and Previous and Next ghost buttons (arrow icons) at the bottom.
- **Empty states:** no messages at all: dashed EmptyState (inbox icon 56 in an `--accent-soft` circle, H2 22 "No messages yet", text 16 muted max-width 420 "When someone fills in the contact form on your website, you will see their message here and get an email.", buttons "Add a form to a page" primary lg and, if not live, the Publish InfoBox). Filtered empty: "Nothing here." 15 muted centred with padding 48.
- **CSV export** (`GET /dashboard/projects/{id}/messages/export`): all non-spam messages, columns Date (ISO 8601 UTC), Name, Email, Phone, Message, Page, Status, Replied; UTF-8 with BOM; filename `{subdomain}-messages-{YYYY-MM-DD}.csv`; cells that start with `=`, `+`, `-` or `@` are prefixed with `'` to prevent spreadsheet formula injection; streamed in pages of 500 rows.
- Freshness: refetch on window focus and every 60 seconds while the tab is visible (also refreshes the sidebar badge).

### 10.3 Public page `/confirm-recipient?token=…`
Minimal layout like the auth pages (logo, centred card max-width 440, padding 32, radius 24). States: success (72 circle `--success-soft`, check 32, H1 28 "Email confirmed", text "You will now get messages from {site} at {email}.", secondary md "Go to Get-On"), expired (warning circle, "This link has expired", "Ask the website owner to send a new one."), invalid (alert circle, "We could not use this link", same help text). Tokens are 32 random bytes (base64url), stored only as a hash, valid 48 hours, single use, and the endpoint is idempotent for an already confirmed address. `noindex`.

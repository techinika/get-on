# UI specification: security (auth, sessions, verification, notification centre, admin security and jobs)

This file holds Sections 7 and 8 of the security hardening task prompt. For sign-in, signup, verification, password reset, account security and the notification centre this file replaces earlier specs.

## 7. UI specification (atom level)
Tokens and components come from `docs/ui-spec.md` and `docs/ui-spec-app.md` (Button, Input, Select, Badge, Dialog, Menu, Toast, InfoBox, Card, ListRow, segmented control, switch row, skeletons, EmptyState, ConfirmDialog, Stepper, avatar). Reuse; do not duplicate. Auth pages use the card layout from the earlier auth spec (page background `--bg`, logo centred at the top, Card below: width `min(440px, 100% - 32px)`, padding 24 (32 from 640), radius 24, shadow card).

### 7.1 Shared auth components
- **`OtpInput`:** a group of **six boxes** (each 48 wide by 56 high at 360 and above, 44 by 52 at 320; gap 8; radius 12; 1.5px `--border-strong`; font 24/32 weight 600 centred; focus: border `--primary` and the focus ring; error: border `--danger` and a 150 ms shake that is disabled under reduced motion). Behaviour: auto-advance, backspace moves back, paste of six digits fills all, `inputmode="numeric"`, `autocomplete="one-time-code"` on the first box, `aria-label="Digit {n} of 6"`, group `role="group"` with a label, submit automatically on the sixth digit (with a visible loading state), digits only. Screen readers hear errors through `role="alert"`.
- **`ResendCode`:** text button "Send a new code" (14/600 `--primary`), disabled with a live countdown "Send a new code in {n}s" during the cooldown (`aria-live="polite"` announces at 30, 10 and 0 seconds), shows "Code sent" for 3 seconds after sending; after the limit shows `OTP_RESEND_LIMIT`.
- **`TurnstileBox`:** renders the widget (managed mode, theme follows the page, 65 high, 300 wide, centred; below 340 it uses the compact size), `aria-live` for failure messages, resets after each failed submit, never blocks keyboard focus order.
- **`PasswordField`:** Input with show or hide button (44x44), live **strength bar** (height 6, radius 3, segments grey, amber, green by score) and plain advice line (13 muted) from the policy; rules shown as a short checklist only when failing ("At least 10 characters", "Not a common password"); breached passwords show the plain error after the server check.
- **`MaskedEmail`:** `a***@gmail.com` style text (15/600) with a "Wrong email?" ghost link where relevant.

### 7.2 Signup (`/signup`, replaces the earlier spec)
Card: H1 28 "Create your free account", sub 16 muted "It takes less than a minute." Fields (gap 16): Full name (optional), Email (type email, `autocomplete="email"`, trimmed, lowercase on blur), Password (`PasswordField`). Two checkbox rows as in the admin prompt (terms required, marketing optional unchecked). `TurnstileBox`. Primary lg "Create my account" (loading "Creating your account..."). Errors: field-level for validation; **banner** (danger, `role="alert"`) for `AUTH_EMAIL_EXISTS` with two inline links "Log in" and "Reset your password" (prefill the email in the login form via a short-lived state, not the URL), `AUTH_EMAIL_EXISTS_UNVERIFIED` shown as an info banner and then the verification page, `AUTH_EMAIL_DISPOSABLE`, `AUTH_PASSWORD_BREACHED`, `RATE_LIMITED`, `TURNSTILE_FAILED`. Google button (secondary lg, Google logo) below a divider; clicking Google without accepting terms shows the consent page first. Footer line "Already have an account? Log in". Timing and wording are identical for the `existing unverified` and `new` branches except the banner.

### 7.3 Verify email (`/verify-email`)
Card: icon mail-check 32 in a 72 circle (`--primary-soft`), H1 28 "Check your email", text 16 muted "We sent a 6-digit code to {MaskedEmail}. It expires in 30 minutes.", `OtpInput`, a **status line** under it (14, `aria-live`): idle hint "Enter the code from your email.", error `OTP_INVALID` with remaining tries, expired state `OTP_EXPIRED` ("That code has expired. We sent you a new one." and the countdown restarts), locked state `OTP_LOCKED`. Below: `ResendCode`, a ghost link "Wrong email? Start again" (confirm dialog; deletes the unverified account and returns to signup), and a help disclosure "I did not get the email" (native details) with plain steps (check spam, check the address, wait a minute, resend; "Still stuck? Write to team@get-on.tech"). Never shows a link-based verification.

### 7.4 Onboarding "Secure your account" (`/onboarding/security`, after verification)
Card (max-width 520): shield-check icon 32 in a 72 circle, H1 28 "Two-step sign-in is on", text 16 muted "Each time you sign in, we email a code to {MaskedEmail}. This keeps your websites safe even if someone learns your password.", a **Recommended** accent chip, a list of three rows with check icons ("A code each time you sign in", "Codes expire in 10 minutes", "We tell you about new devices"), a **test code step**: button "Send me a test code" (secondary md) then `OtpInput` ("Enter the code to confirm your email works"), then primary lg "Continue" (disabled until confirmed when policy is `required`; when `recommended` also shows the ghost "Skip for now" and the option can be changed later). Existing users see this once after their first code.

### 7.5 Login (`/login`) and code step (`/login/verify`)
- **Login card:** H1 28 "Welcome back", sub "Log in to manage your website.", Email, Password (with "Forgot password?" link), `TurnstileBox` (only after 3 failures), primary lg "Log in" (loading "Logging in..."), divider, Google button, footer "New here? Create a free account". Banner for the rollout (30 days): info InfoBox "We added two-step sign-in. After you log in, we email you a code." The error banner uses `AUTH_INVALID_CREDENTIALS` or `AUTH_LOCKED` (with the remaining time).
- **Code card:** icon mail 32 in a 72 circle, H1 28 "Enter your sign-in code", text "We sent a 6-digit code to {MaskedEmail}. It expires in 10 minutes.", `OtpInput`, status line as above, `ResendCode`, ghost "Use a different account" (logs out and returns to login), small text 13 muted "This was not you? Change your password" (link to forgot password). A "Having trouble?" disclosure with the plain help steps and a note "We cannot skip this step for you" (explains why support cannot bypass). Auto-focus on the first box; on success a brief check state (150 ms) then redirect.
- Staff entering `/admin` see the same code card titled "Confirm it is you to open the staff area".

### 7.6 Forgot and reset password
- `/forgot-password`: H1 28 "Reset your password", text "Enter your email and we will send you a link.", Email, `TurnstileBox`, primary lg "Send reset link". After submit always: check circle 56, H2 "Check your email", text "If that address has an account, a reset link is on its way. The link works for 30 minutes.", ghost "Back to log in". No difference between existing and unknown addresses.
- `/reset-password?t=`: shows a form only: H1 28 "Choose a new password", `PasswordField`, confirm field, primary lg "Save new password" (loading "Saving..."); invalid or used token: generic card "That link is no longer valid." with "Ask for a new link". Success: check circle, "Your password was changed. You were signed out everywhere. Log in with your new password." then login.

### 7.7 Account security (`/dashboard/account/security`, narrow container 720; linked from the account menu and the Account page)
PageHeader "Security", description "Keep your account safe." Cards (gap 24):
1. **Two-step sign-in** (padding 24): left shield icon tile 48, title 17/600 "Two-step sign-in", status chip "On" (success), text 15 muted "We email a code to {MaskedEmail} each time you sign in." Read-only when policy is `required` ("Always on for every account"); when `recommended` a switch row with a ConfirmDialog for turning it off. Row "Last code sent {time}" 13 muted and a "Send a test code" ghost md.
2. **Password** (padding 24): "Last changed {date}" and "Change password" secondary md opening a Dialog (480): Current password, New password (`PasswordField`), Confirm, then the step-up code (`OtpInput`) — the dialog sends the code when it opens — buttons "Cancel" and "Change password" (loading "Saving..."). Success toast and an InfoBox "You were signed out on your other devices."
3. **Email address** (padding 24): masked current email, "Change email" secondary md opening a Dialog (480) with a 3-step Stepper: New email and current password, code sent to the old address, code sent to the new address; after success the toast and a note about the undo link we emailed.
4. **Active sessions** (padding 0): rows (min-height 72, padding 12 20): device tile 40 (monitor or smartphone icon), "{Browser} on {System}" 15/600, "Current session" success chip or "Last active {relative time}" 13 muted, "{Country}" 13 muted, a "Sign out" secondary sm (not on the current row); a footer row with "Sign out everywhere else" (danger-outline md; ConfirmDialog + step-up). Empty state not needed (at least the current session).
5. **Security activity** (padding 0): the user's own security events for 12 months with filter Select (Everything, Sign-ins, Codes, Password and email, Devices); rows (min-height 64): icon tile 36 by category (neutral), summary 15/600 ("Signed in from Chrome on Windows"), meta 13 muted ("Mar 12, 14:02 UTC, Rwanda"), severity chip for warnings; "Show more" (25 per page); each row for a failed attempt shows "This was not you?" ghost sm linking to the not-me page.
6. **Help** (collapsible): plain text about what Get-On will never ask ("We never ask for your code by email, phone or chat").
Loading skeletons; error InfoBox with "Try again".

### 7.8 Not me page (`/security/not-me?t=`, minimal layout)
Card: alert circle 56 (`--warning-soft`), H1 28 "Secure your account", text 16 muted "If you did not try to sign in, we can sign out every device and ask you to choose a new password.", primary lg "Secure my account" (POST; loading "Securing..."), ghost "This was me" (closes). Success: check circle, "Your account is secured. Check your email to choose a new password." Invalid token: generic card. `noindex`, `no-referrer`.

### 7.9 Step-up dialog (global, 440; sheet below 640)
Opens whenever an action returns `STEP_UP_REQUIRED`: lock icon tile 48, H3 "Confirm it is you", text 15 muted "We sent a code to {MaskedEmail}. Enter it to continue.", `OtpInput`, `ResendCode`, buttons "Cancel" and "Confirm" (primary md; loading "Checking..."). On success the original action retries automatically; the dialog remembers nothing else. Focus trapped; Escape cancels.

### 7.10 Notification centre
- **Bell button** in the dashboard top bar (44x44, bell icon 20; badge 18 min width, `--primary` background, white 11/700 for unread up to 99, "99+"; hidden when 0) before the Help button; in the admin top bar too (staff notices). Keyboard operable, `aria-label="Notifications, {n} unread"`.
- **Panel** (popover 400 wide, max-height 560, radius 16, shadow raised; bottom sheet below 640): header (padding 16 20, "Notifications" 16/700, "Mark all as read" ghost sm), tabs "Unread" and "All" (segmented control height 40), list rows (min-height 72, padding 12 20, top divider): severity icon tile 36 (info `--info-soft`, warning `--warning-soft`, danger `--danger-soft`, success `--success-soft`), title 15/600 (700 when unread, with an 8 px `--primary` dot), body 14/1.5 muted (two-line clamp), time 12 muted, an action button (secondary sm) when `actionUrl` exists; hover reveals "Mark read" and "Dismiss" 36x36 icon buttons. Footer link "See all notifications" (page). Empty: bell icon 40 in a 72 circle, "You are all caught up."
- **Page** (`/dashboard/notices`, default container 960): list Card with filters (All, Unread, Billing, Security, Websites, Team), "Mark all as read"; infinite "Show more" (25 per page).
- **Banners:** sticky critical notices render as the existing banner component at the top of the dashboard (max two visible, the rest in "More"), each with its action and an `aria-live="polite"` announcement on first render; dismissible only when the notice is non-critical.
- Preferences are not needed for in-app notices (always on); email preferences stay as designed.

### 7.11 Accessibility and responsive rules
Every auth screen is usable at 320 px; code entry works with keyboard, paste, password managers and screen readers; errors are announced; no information is colour-only; focus is managed on step changes; countdowns do not trap focus; reduced motion disables the shake and fades; all auth pages are `noindex`, `no-store` and use `Referrer-Policy: no-referrer`.

## 8. Admin, docs, legal and retrofit

### 8.1 Admin console additions (staff boundary rules unchanged)
- **Security page** (`/admin/security`; customer success view, super admin full): cards for the last 24 hours and 7 days: sign-in successes, failures, lockouts, codes sent, codes verified, codes failed, code email delivery failures, registrations blocked (duplicate, disposable, rate limited), Turnstile failures, active blocked IP hashes (count), password resets requested, "not me" reports; charts (failures and lockouts per hour) using the shared chart; tables: **Active blocks** (IP hash prefix, reason, until, "Clear" for customer success? (`security.unlock` direct) and super admin "Block an IP hash" with a reason), **Locked accounts** (masked email, reason, until, "Clear lockout" direct for customer success with reason and case), **Recent critical events** (metadata only). No code values, no full emails, no content.
- **Jobs page** (`/admin/platform/jobs`; super admin full, customer success view): table (Job, Schedule in plain words and cron, Priority, Last run (status chip, time, duration), Next run, Failures in a row, Lateness, Critical chip), a run history drawer per job (last 50 runs with errors and counts), a "Run now" button (super admin; idempotent jobs only; step-up and reason), health summary at the top ("All jobs on time" or the list of problems), and the **reminders SLO** panel (sent on time percentages, lateness percentiles). A "Download job inventory" button (super admin) exports the registry.
- **Settings** (`/admin/platform/security-settings`, super admin): edit the `security_settings` values with plain explanations, `two_factor_policy` selector with a ConfirmDialog warning ("Changing this affects every account"), registration open toggle, blocked email domains and disposable domain list editor (add and remove with audit), all with step-up and audit.
- **Staff matrix additions:** `security.view` (S, C view), `security.unlock` (S direct, C direct for lockouts only), `security.block_ip` (S), `security.settings` (S dual when 2+ super admins), `jobs.run` (S), `jobs.view` (S, C view). Regenerate the matrix, SQL and docs.

### 8.2 Legal
- **Privacy Policy:** security logging (sign-in events, device and browser family, country, hashed network identifiers, retention 12 months for the user's own security events and 30 days for signup attempts), emailed sign-in codes (what is stored: hashes only, deleted after 24 hours), sessions and devices, abuse prevention (blocking), Turnstile (processed by Cloudflare), notifications and reminders.
- **Terms of Service:** account security responsibilities (keep the email inbox secure, do not share codes), our right to lock or suspend accounts for suspected compromise or abuse, account recovery process and waiting period `[[DECISION: wording; lawyer review]]`.
- **Cookie Policy:** add `__Host-gs_chal` (verification challenge binding, 30 minutes), `__Host-gs_dev` (device recognition, 1 year), session cookies, the Turnstile service cookies as described by Cloudflare, and the notification state (none stored beyond account data).

### 8.4 Manual steps documented for the owner (and listed in the final summary)
Auth service settings to apply (confirm email on, public signup closed or hook enabled, JWT lifetime 15 minutes, auth emails disabled, redirect URLs, rate limits aligned), Cloudflare dashboard (Turnstile hostnames and domains, WAF managed rules, rate limiting rules for `/api/auth/*`, bot protection, the cron trigger deployment for the jobs Worker), SES (priority sending quota, bounce handling for the code emails), secrets creation and rotation calendar, running the audit and repair scripts, reviewing the duplicates report, deciding `required` versus `recommended` before launch.

### 8.5 Retrofit list
Replace every direct client-side signup or sign-in call with the server endpoints; remove Supabase auth emails and any verification link; update invitation acceptance, Google callback and onboarding; replace staff MFA code with elevation and step-up; add `requireVerifiedSession` to every route and action from the audit; generate and apply the restrictive policies; replace every raw `fetch` of a user-influenced URL with `safeFetch`; encrypt the listed fields; register every job in the scheduler and delete any ad hoc cron configuration; wire reminder rules for every item in Section 9 (replacing ad hoc schedulers inside billing, domains, invitations and backups jobs); add `inApp` definitions to the notification catalogue.

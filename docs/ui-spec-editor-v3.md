# Editor v3 UI and AI specification

> The editor is replaced by `docs/ui-spec-editor-v3.md`. Where they conflict, v3 wins.

## 9. Editor UI specification (atom level)
Tokens and components come from `docs/ui-spec.md` and `docs/ui-spec-app.md`. Reuse them. **Dense desktop controls** in the editor (fine pointer devices) may be 32 to 36 px high with hit areas of at least 28 px; on coarse pointers every control is at least 44 px (the earlier tap target rule applies).
### 9.1 Shell and layout
- Route: the project's page editor route (replaces the earlier one); full viewport height (`100dvh`), no page scroll; the shell is a CSS grid: top bar (56) over a body row.
- **Outer margin:** 12 px on each side and below the top bar (8 px below 1280), **gap 12 px** between panels. Panels are cards (background `--surface`, 1px `--border`, radius 16, overflow hidden).
- **Columns:** left panel default **320** wide (resizable 280 to 420 by dragging a 6 px handle on its right edge, double click resets, the width is remembered per user), centre fluid (minimum 480), right panel default **360** (resizable 320 to 480). Both panels collapse with 36x36 edge buttons (chevrons; keyboard `Ctrl/Cmd + [` for left and `Ctrl/Cmd + ]` for right); when collapsed the canvas widens; a collapsed panel leaves a 36 px vertical rail with its tab icons.
- **Breakpoints of the editor itself:** at 1600 and above, panels 340 and 380 by default; at 1280 to 1599 as above; at 1024 to 1279 the left panel opens as a 280 px overlay (it covers part of the canvas while open and closes after inserting) and the right panel stays docked at 320; below 1024 the touch layout of 9.15 applies.
- **Canvas column:** canvas toolbar (48), canvas area (flex 1), breadcrumb bar (32), optional developer drawer (Section 9.13). The developer drawer sits **below the canvas** inside the centre column.
### 9.2 Top bar (56 px, background `--surface`, bottom border 1px `--border`, padding 0 12)
Left group: "Pages" back button (arrow-left, ghost md), divider, the **page switcher** (title with chevron; menu as in the earlier spec), "Home" badge, the **save status chip**. Centre group: the **selection path** is **not** here (it is in the bottom breadcrumb). The centre of the top bar is intentionally empty except at ≥ 1600 where the **site and page style entry** buttons appear: "Page" and "Site" ghost md with sliders and palette icons (they select the page root and the Site tab). Right group: **"Generate page with AI"** (primary-accent button: height 36, padding 0 14, background `--accent-soft`, text `--accent-text` 14/700, sparkles icon 16, hover `--accent`; always visible, never in the overflow menu; at < 1280 shows the icon and the text "Generate"), Undo and Redo (36x36 ghost icon buttons), Page tips chip, balance chip (existing), **Share**, **Preview in new tab** (external-link ghost icon, opens the private preview route), **Settings** (gear, opens the editor settings, 9.14), "Publish" (PublishButton). Template mode swaps Publish for "Save template" and adds "Details" (existing behaviour).
### 9.3 Canvas toolbar (48 px, inside the centre column above the canvas area; background `--surface`, radius 16 on top, border bottom 1px `--border`)
Left: **Insert** toggle (plus icon 36x36, opens the left panel's Add tab when it is collapsed) and **List view** toggle (layers icon, opens the Layers tab), then a vertical divider. **Centre (the mode switch, exactly at the middle top of the canvas):** segmented control "Edit | Preview" (height 36, width 172, two segments with icons pencil and eye, active segment background `--surface`, shadow card, `aria-pressed`, shortcut `Ctrl/Cmd + Alt + P`; switching animates in 150 ms, none under reduced motion). Right: **device group** (segmented icon buttons 36x36: Desktop (monitor), Tablet (tablet), Phone (smartphone); a "…" menu with more presets: Large screen 1440, Laptop 1024, Small phone 320), the **width field** (Input 72 wide, number, shows the frame width in px; typing a value between 320 and 1920 sets a custom width and shows "Custom"), the **zoom Select** (Fit, 50, 75, 100, 125, 150, 200 percent; `Fit` is default and recomputes on resize and panel changes), **"Select mode"** toggle (cursor icon: navigation mode, Section 9.6), and the **Code** button (code icon) **only when developer tools are enabled** (9.13).
### 9.4 Canvas area
- Background `--surface-muted` with a subtle dot grid (1 px dots every 16 px at 6 percent of `--text`), padding 24 (16 below 1280) on all sides so the page frame never touches the panels.
- **Page frame:** an iframe (`title="Page canvas"`) rendered at the **real device width** (Desktop default 1280, Tablet 768, Phone 390, custom 320 to 1920) and scaled with `transform: scale(k)` and `transform-origin: top center` inside a wrapper sized to the scaled dimensions; frame radius 12, 1px `--border`, shadow card, background from the theme; the iframe height equals its content height (observed with `ResizeObserver`), the canvas area scrolls vertically; horizontal scroll only when zoom makes the frame wider than the area. The frame has **resize handles** (left and right edges, 10 px wide hit areas) to drag the width (snap to 320, 390, 768, 1024, 1280 within 12 px; hold Alt to disable snapping) with a floating width label ("847 px").
- **Frame contents:** the real page rendered by the shared renderer with the theme tokens, fonts and all CSS layers; header and footer render as part of the page (selectable parts); an editor layer (overlays) lives in the same iframe document through a portal.
- **Empty page state:** centred card (max-width 480): icon layout-template 40 in a 72 circle (`--accent-soft`), H2 22 "Start your page", text 15 muted "Add elements and sections from the left, or let AI write the page.", buttons "Generate page with AI" (primary-accent md), "Choose a template section" (secondary md), "Add an element" (ghost md).
- **Loading and error:** skeleton frame while the iframe boots; if the canvas crashes show an InfoBox danger "The canvas stopped working" with "Reload canvas" (state preserved).
### 9.5 Edit mode: selection, hover, toolbars, insertion, drag and drop
- **Hover:** 1px dashed outline `--primary` at 60 percent, offset -1, with a **name chip** (height 20, padding 0 6, radius 6, 11/700, background `--primary`, text white) at the top-left outside the element (inside when there is no room); no chip on text being edited.
- **Selection:** 2px solid outline `--primary`, offset -2, name chip persistent, **resize handles** where relevant (8 px squares with 2px white border: images (width and height with aspect lock via Shift), columns (a vertical divider handle between columns changes `span` or widths; shows percentages live), spacers (a bottom handle changes height), containers with fixed height (bottom handle)).
- **Spacing overlays:** when the Spacing group of the inspector is open, or while holding Alt over a selected element, show **margin** (soft orange `rgba(245,165,36,0.28)`) and **padding** (soft green `rgba(11,107,79,0.22)`) overlays with draggable handles on each side (drag to change the value; Shift links opposite sides; values shown in a pill); in the Layers panel the same overlays toggle with "Show spacing".
- **Floating element toolbar** (above the selection, flips below when no room; height 40, radius 10, background `--surface`, 1px `--border`, shadow raised; buttons 32x32 icons 18, gap 2, dividers 1x20): drag handle (grip), move up and down (arrows), **select parent** (corner-left-up), **transform to** (menu of compatible types, for example paragraph, heading, list, quote; container to row or stack), alignment (for text and images), link (for text, button and image), the **AI** menu (sparkles: Rewrite, Change the look, Make responsive, Fix layout, Add content, Explain), and **More** (menu: Duplicate, Copy, Cut, Paste, Paste styles, Group, Ungroup, Lock or Unlock, Hide on devices, Save as pattern, Convert to elements (smart sections), Delete). On touch devices the toolbar docks at the bottom.
- **Insertion points:** between siblings and at the end of containers a **"+" circle (24 px)** appears on hover on the gap (and always on touch): click opens the **inserter popover** (width 360, height 440): search, tabs (Elements, Sections, Patterns, Saved), plus a first row "Generate here with AI" (sparkles; opens the AI prompt popover for a section at this position). Empty containers show a dashed 64 px placeholder with "Add an element". Typing `/` at the start of an empty paragraph opens the **slash menu** (list of elements with keyboard filtering; Enter inserts; Esc closes).
- **Drag and drop (from the canvas, Layers and the Add panel):** pick up by the drag handle (or press and hold 250 ms on touch); a ghost chip follows the pointer (element name and icon, opacity 0.9); the **drop indicator** is a 3 px `--primary` line with an 8 px end circle for sibling insertion and a 2px dashed `--primary` outline with `--primary-soft` fill at 20 percent for dropping **into** a container; the target is computed with `elementFromPoint` inside the iframe corrected for scale; rules: only allowed parents accept (disallowed targets show a not-allowed cursor and a tooltip "A column can only go inside a row"); auto-scroll near the edges of the canvas; `Esc` cancels; keyboard alternative: focus the drag handle, Space to pick up, arrows to move among valid positions, Space to drop (live region announcements: "Picked up Heading. Position 2 of 5 in Hero section.").
- **Multi-select:** Shift or Ctrl/Cmd click adds siblings or arbitrary nodes; the inspector shows **mixed** values ("Mixed") and edits apply to all; operations: group (into a container), delete, duplicate, move together, copy, style copy and paste, align.
- **Copy and paste:** copy writes the subtree JSON with the prefix `gs-clipboard:v5:` to the clipboard (and localStorage fallback); paste inserts after the selection (or into a selected container) after validation, id regeneration and cross-site media handling (media from other websites are dropped with a toast); pasting plain text creates paragraphs; pasting HTML from other sources is sanitised into allowed elements.
- **Keyboard (listed in the shortcuts dialog):** `Esc` toggles **select mode** (arrows move between nodes, Enter enters edit, Tab moves to the toolbar), `Ctrl/Cmd + Z`, `Ctrl/Cmd + Shift + Z`, `Ctrl/Cmd + D` duplicate, `Delete` or `Backspace` remove (with an undo toast), `Alt + ↑` and `Alt + ↓` move, `Alt + ←` select parent, `Alt + →` select first child, `Ctrl/Cmd + G` group, `Ctrl/Cmd + Shift + G` ungroup, `Ctrl/Cmd + C`, `X`, `V`, `Ctrl/Cmd + Alt + C` and `Alt + V` copy and paste styles, `Ctrl/Cmd + K` link, `Ctrl/Cmd + J` AI, `/` inserter in empty paragraphs, `Ctrl/Cmd + S` save now, `Ctrl/Cmd + Alt + P` preview, `Ctrl/Cmd + Alt + D` developer drawer (when enabled), `Ctrl/Cmd + [` and `]` panels, `?` shortcuts.
### 9.6 Preview mode
Toggled at the canvas toolbar. The frame renders the **published output**: no outlines, overlays, placeholders or editor affordances; hover and focus states and transitions are live; the menu, accordions and anchors work; internal links navigate to the target page's preview inside the frame (breadcrumb shows the page path with a back button); forms are inert with the existing caption; device and zoom controls stay active; the right panel shows a muted state "Preview mode. Switch to Edit to change styles." and the left panel remains usable for pages only. A small chip at the top-left of the frame "Preview" (accent soft). Switching back restores the previous selection and scroll position. "Preview in new tab" opens the private preview link route.
### 9.7 Left panel
Header (height 48): two tabs **Add** and **Layers** (segmented, plus a third icon button **Pages** that opens the page list popover), collapse button.
**Add tab:** search Input (height 36, search icon, placeholder "Search elements and sections", debounce 150 ms, synonyms from the registry) and a **filter row** (chips: All, Elements, Sections, Template sections, Saved, Plugins; height 32). Below the search, the **AI row** (full-width card, padding 12, radius 12, background `--accent-soft`, sparkles icon tile 32, text 14/600 "Describe a section", Input "For example: three pricing cards with a highlighted middle plan", `CreditChip`, Go button) that creates a section with AI at the insertion point (selected node or end of page).
- **Elements** (accordion groups with 2-column tiles; tile 100 wide by 88 high (flexible), padding 12, radius 12, 1px `--border`, icon 24 above a 13/600 label, hover border `--primary` and shadow card; drag or click to insert; keyboard focusable): *Layout* (Section, Container, Row (with column presets 1, 2, 3, 4, 1:2, 2:1, 1:3, 3:1), Grid, Stack, Card, Spacer, Divider), *Text* (Paragraph, Heading, List, Quote, Table, Code), *Media* (Image, Gallery, Icon, Video link, File download, Map card), *Actions* (Button, Buttons, Link list, Accordion), *Advanced* (HTML), *Plugin elements* (grouped per plugin with an On or Off chip; locked tiles show a lock and the line "Turn on {Plugin}" which opens the enable dialog; locked tiles are never draggable).
- **Sections** (smart sections): list rows (min-height 72, padding 8 12): thumbnail 96x60 (a live scaled render using the site theme, lazy), name 14/600, description 12 muted; click or drag inserts at the insertion point or end of the page.
- **Template sections** (patterns): cards in a single column (width 100 percent minus padding; each: live preview 16:10 radius 12, name 13/600, tag chips 11/700); filter chips (categories), style chips (Light, Dark, Minimal, Bold), the toggle "For my business type", sort (Recommended, Newest); a **"Browse all templates"** link opens the Templates gallery in a modal to pull a **section from a whole template** (the template's pages and sections are listed with previews; choose sections to insert). Loading skeletons; infinite scroll in pages of 12.
- **Saved:** the team's patterns (synced chip when synced), search, usage counts, kebab (Rename, Edit pattern (opens it in a focused edit view), Duplicate, Delete).
- Insert behaviour: with a node selected, new elements insert **after** the selection (or into it when it is an empty container); with nothing selected, at the end of the page; sections always insert at the page root level.
**Layers tab:** a tree (`role="tree"`, rows 32 high, indentation 16 per level, expand chevrons, node icon, name (double click or F2 to rename), type chip (11 muted) for unnamed nodes, eye icon (hide on all devices), lock icon, drag handle on hover; selected row background `--primary-soft`); drag and drop to reorder and to nest (same drop rules and indicators as the canvas); context menu mirrors the toolbar More menu; search Input with "highlight matches"; a toggle "Show spacing"; **virtualised** above 300 rows; synced with canvas selection (selecting scrolls the layer into view and vice versa); a footer with node count and a warning near the limit ("1,820 of 2,000 elements").
### 9.8 Right panel (inspector)
Header (height 56): icon tile 32 with the selected element's icon, name 15/600 (editable on double click), a **breadcrumb dropdown** (chevron-down; lists ancestors to select), and an actions kebab (Copy styles, Paste styles, Reset all styles, Save styles as preset, Apply preset, Duplicate, Delete). **Device and state bar** (height 44, padding 0 12): segmented Desktop, Tablet, Phone (icons; a 6 px dot on a device that has overrides) and a **State Select** (Normal, Hover, Focus, Active). **Tabs** (sticky, height 44): **Settings**, **Style**, **Advanced**. With nothing selected the tabs are **Page**, **Site**, **Tips**.
- **Style tab:** top row: search Input "Find a style" (filters controls across groups) and the **AI row** ("Describe how it should look", Input with sparkles, `CreditChip`, Go; Section 10.4). Below, **accordion groups** (each header 44 high with chevron, title 13/700, a 6 px dot when the group has values at the current device and an inline reset icon (undo arrow) that resets the group): **Layout**, **Size**, **Spacing**, **Position**, **Typography**, **Background**, **Border**, **Effects**, **Transform and transition**. Groups appear only when the element supports them (registry `styleCapabilities`). Groups remember their open state per element type. **Inherited and overridden indicators:** a control label with a filled dot means set at this device; a hollow dot means inherited from a larger device; hovering shows "Desktop: 32 px". **"Copy desktop to {device}"** appears in the group header menu when editing Tablet or Phone.
- **Settings tab:** element props (content props, link target, image selection, tag choice, columns count, layout variants as option cards) and for smart sections the earlier Edit and Style fields grouped under their labels; plugin-dependent elements show the plugin state and a "Turn on" action; **"Convert to elements"** for convertible smart sections.
- **Advanced tab:** **HTML tag** (Select where applicable), **Anchor (ID)** (Input with `#` prefix, validation, copy link button), **Additional CSS class(es)** (token input: type and press Enter or comma; chips with x; suggestions from existing classes and presets; validation message "Use lowercase letters, numbers, dashes and underscores."), **ARIA label**, **Title**, **Data attributes** (list editor, max 10), **Show on** (three switches Desktop, Tablet, Phone), **Lock** switch ("Prevent moving and deleting"), **Layer name**, **Editor note** (Textarea, max 200, shown only in the editor), and **Custom CSS** (CodeMirror editor, height 160 with "Expand" to the developer drawer, placeholder `selector {\n  /* your CSS */\n}`, helper "Use selector to style this element. Your CSS only affects this element and what is inside it.", live preview debounced 150 ms, inline issues, size meter "0.4 of 4 KB", buttons "Format", "Revert", "Ask AI"); a collapsed disclosure "What can custom CSS do?" with the allowed and blocked rules in plain words.
- **Page tab (nothing selected):** **Page styles** (the page root's Style groups: background, content width default, typography defaults (font size scale, line height), spacing, overflow), **Page CSS** editor (same component, 20 KB), **Page settings** (title, address, show in menu as before), SEO fields (existing), anchors list (all ids on the page with links), and the existing "Page" options.
- **Site tab:** the existing **Design** controls (colours with the colour wheel, fonts via the font picker, buttons, cards, corners, spacing density, rhythm), **Header and footer** (Section 9.12), **Style presets manager** (list, rename, delete, usage counts), **Site CSS** editor (plan size limit, with the size meter), **Global element defaults** (default styles for paragraph, headings, links, buttons as presets applied to new elements).
- **Tips tab:** the existing Page tips extended with style and tree checks (Section 12).
### 9.9 Style controls (atom level; each control is a reusable component with keyboard and touch support)
- **NumberUnit field:** a 32 high input group (number input 56 wide + unit `Select` 56 wide + optional slider below or inline), label 12/600 above; arrow keys step by 1 (Shift 10, Alt 0.1), `Home` and `End` for min and max, drag-to-scrub on the label (cursor ew-resize, shows a tooltip), unit change converts the value when possible, `Reset` icon appears on hover when set, invalid values turn the border `--danger` with the plain message. Units per property from 5.2.
- **Box (margin and padding) widget:** a nested box diagram 280x180: outer rectangle labelled "Margin", inner "Padding", centre "Content"; four value inputs (top, right, bottom, left) per layer positioned on the sides (44 wide, 28 high); a **link toggle** (chain icon) per layer (all sides, vertical pair, horizontal pair), `auto` allowed for margin; quick-scale chips (0, 4, 8, 16, 24, 32, 48, 64, 96) below; the diagram highlights the edge being edited on the canvas overlay.
- **Layout picker:** segmented **Display** (Block, Flex, Grid, None); for Flex: **direction** (four icon buttons), **wrap** (switch), **justify** and **align** as a **3 by 3 alignment grid** plus extra buttons for space-between and stretch, **gap** (linked row and column gap NumberUnit); for Grid: **columns** control (count stepper 1 to 12 with live preview strips; "Auto fit (min width)" mode with a NumberUnit; "Custom tracks" list editor of lengths and `fr`), rows, gap, `place-items` 3 by 3 grid, auto flow; **child placement** controls (column and row span, order) appear for children of grids and flex rows.
- **Size controls:** width, min, max, height, min, max as NumberUnit with the keyword buttons `auto`, `100%`, `fit-content`, `min-content`, `max-content`; aspect ratio Select (Auto, 1:1, 4:3, 3:2, 16:9, 21:9, 3:4, 4:5, Custom); overflow segmented (Visible, Hidden, Scroll, Auto); object fit Select (Cover, Contain, Fill, None) with a 3 by 3 object position grid for images.
- **Typography group:** **Font family** (a Select that shows the family name in its own face, opens the font picker dialog (existing) with "Theme heading", "Theme body" at the top), size (NumberUnit with a **fluid** toggle that exposes min and max sizes), weight (Select with numeric weights available for the family), style (italic toggle), line height, letter spacing, word spacing, transform (segmented: Aa, AA, aa, none), alignment (four icon buttons), decoration (underline, strike, none with colour and thickness popover), white space, columns (count, gap, rule), text shadow (layers editor shared with box shadow), **text colour** (colour field, 9.10).
- **Background group:** a segmented **Type** (None, Colour, Gradient, Image, Multiple layers); colour field; **Gradient editor** (preview bar 32 high with draggable stops (14 px handles; click adds, drag removes by pulling off, 2 to 6 stops), stop colour popover, position input, type Select (Linear, Radial, Conic), **angle dial** (64 px circle with a handle; numeric input), presets row (8 gradients from the theme palette)); **Image** (Image field opening the picker, size Select (Cover, Contain, Auto, Custom), position **3 by 3 grid** and focal point toggle "Use the picture's focus point", repeat Select, attachment Select (Scroll, Fixed (not on phones)), **overlay** controls (colour, opacity slider 0 to 80), blend mode Select).
- **Border group:** side selector (All, Top, Right, Bottom, Left) with per-side width, style (Select: none, solid, dashed, dotted, double), colour; **radius** widget (four corner inputs with a link toggle and a live preview square 48x48; "Pill" and "Circle" quick buttons); outline (width, style, colour, offset).
- **Effects group:** **Box shadow** layers editor (up to 6 layers; each layer row: x, y, blur, spread, colour, inset switch, visibility eye, delete; presets chips: None, Soft, Medium, Large, Outline, Inner; preview swatch 56x56), opacity slider 0 to 100, **filters** (sliders for blur, brightness, contrast, grayscale, hue, invert, saturate, sepia with Reset), backdrop blur slider, blend mode Select, clip shape presets (None, Slant, Curve, Circle, Ellipse, Custom polygon with a points editor), cursor Select.
- **Position group:** segmented position (Static, Relative, Absolute, Sticky) with a warning chip "Fixed is not available" tooltip; offset **box widget** (top, right, bottom, left) with `auto`; z-index NumberUnit; a note when absolute is used without a positioned parent.
- **Transform and transition:** translate X and Y, rotate (dial), scale (linked slider), skew; origin 3 by 3 grid; transitions list editor (property Select, duration, delay, easing Select: Linear, Ease, Ease in, Ease out, Ease in out, Spring-like (cubic-bezier preset)); a "Preview hover" button that applies the hover state for 1 second on the canvas.
- **Visibility and responsive hide:** in the Advanced tab; also a quick eye in the toolbar.
- **Text colour field and every colour field:** a 32x32 swatch button (checkerboard under transparent) plus the hex text (monospace 13) opens the **colour popover** (the earlier wheel, hex, RGB, eyedropper, saved and recent colours) with **theme swatches first** (a row of the theme tokens as 28 px circles with names on hover), then "My colours", an **opacity slider**, and a **contrast badge** against the effective background (AA and AAA chips, "Fix it" button adjusts lightness minimally); choosing a theme token stores the **token** (stays linked to the theme), choosing any other colour stores the hex.
- **Presets:** each group header menu offers "Presets" with a few named looks relevant to the group (for example Shadows: Soft, Lifted, Hard; Borders: Subtle, Strong, Rounded card; Typography: Display, Body, Caption) applying style sets that use tokens.
### 9.10 Rich text editing
- Elements with text edit **in place** inside the iframe using Tiptap (headless) attached to the real DOM element (same classes and styles, so the look never changes while typing). Entering edit mode: click on text, or press Enter in select mode.
- **Floating inline toolbar** (appears above the selected text, height 40, background `#1F1A17`, buttons 32x32 white icons 18, radius 10): Bold, Italic, Underline, Strike, Link (popover with the Link field: page, section, website, phone, email, WhatsApp, "Open in new tab"), Inline code, **Text colour** (colour popover from 9.9, tokens first), **Highlight**, More (Subscript, Superscript, Small caps, Clear formatting), **Transform to** (Paragraph, Heading 1 to 6, Bulleted list, Numbered list, Quote), **Alignment** (left, centre, right, justify), **Dynamic field** (inserts a `field` chip: menu of business name, tagline, phone, email, address, city, opening hours summary, year, web address; chips render the real value in the editor with a dotted underline and show "From business details" on hover; backspace deletes the chip), and **AI** (sparkles: Rewrite, Shorter, Longer, Fix, Friendlier, Professional, Simpler, Custom instruction; applies to the selection or the whole element).
- **Block behaviours (Gutenberg style):** Enter creates a new paragraph; Shift+Enter inserts a line break; Backspace at the start of an empty paragraph removes it and moves focus to the previous text; Enter twice in a list exits it; Markdown shortcuts (`#`, `##`, `###`, `-`, `*`, `1.`, `>`, `**bold**`, `_italic_`, `` `code` ``); `/` opens the slash menu; paste cleans Word and Google Docs HTML into the allowed schema, plain text splits into paragraphs, pasted URLs offer "Make it a link"; spell check follows the editor setting; IME composition is never interrupted by re-rendering; undo and redo are merged with the global history (800 ms grouping).
- **Button label** uses a lite editor (bold, italic only); **table cells** use inline rich text; **headings** allow inline marks except links to avoid clashing with styles (allow links).
- Plain text elements with limits (for example `props.text` of smart sections) keep their counters from the earlier panel fields.

### 9.12 Header and footer parts
Selecting the header or footer in the canvas shows their structured settings in the Settings tab (existing options). A **"Customize layout"** button converts the part into an editable tree built from primitives plus the **connected elements** `nav-menu` (renders the website menu from pages and sections with style controls for layout, gap, link style, active state and a CTA slot), `site-title` (the business name as typographic text; **never an icon or letter mark**; or the logo image) and `logo`; the tree is saved in `project_settings.editor_header_tree` or `editor_footer_tree` and used on every page; "Revert to settings" discards the tree after confirmation. The Free-plan badge region is **not** part of the footer tree (Section 6.5). In the Layers tab the header and footer appear as pinned top and bottom entries with a lock on structure when using the structured settings.
### 9.13 Developer tools drawer (hidden by default)
Enabled in the editor settings ("Show developer tools"). When on, a **drawer** appears below the canvas (inside the centre column, between the canvas and the breadcrumb bar), default height 260, resizable by dragging its top edge (160 px to 60 percent of the column), collapsible to a 36 px bar, toggled by the Code button or `Ctrl/Cmd + Alt + D`. Tabs: **HTML** (the rendered HTML of the selected element, or the page when nothing is selected; read-only CodeMirror with copy and "Open in a new tab"), **CSS** (the compiled CSS for the selected element in three read-only groups (structured styles, preset, custom) plus an **editable custom CSS editor** bound to the element; when nothing is selected it edits the page CSS), **Tree** (the node JSON of the selection, **editable** behind an "Edit" toggle with validation, a diff preview and "Apply" as one undo step), **Issues** (sanitiser, lint, accessibility and duplicate id messages with "Select" links), **Site CSS** (site-level CSS editor). The drawer never shows or sends anything to staff or third parties; copy buttons only. Syntax highlighting, line numbers, bracket matching, search, autocomplete for CSS properties and allowed values, `Ctrl/Cmd + /` comment toggle.
### 9.14 Editor settings (gear dialog, 560 wide)
Switches and selects (stored in `profiles.editor_prefs`, applied instantly): **Show developer tools** (default off), **Show spacing overlays on hover** (default on), **Snap to guides** (default on), **Show element names on hover** (default on), **Spell check** (default on), **Default device** (Desktop, Tablet, Phone), **Remember panel sizes** (on), **Reduce motion in the canvas** (follows the system setting), **Confirm before deleting sections** (default off since undo exists), **Auto-open the inspector on selection** (on), **Show layers by default** (off), **Use large controls** (touch-friendly sizes). A "Keyboard shortcuts" link and "Reset editor layout" button.
### 9.15 Touch and small screens (below 1024)
Panels become sheets: **Add** and **Layers** open from a bottom bar (icons Add, Layers, Style, AI, More) as sheets (peek 104, half 50dvh, full 90dvh as in the earlier spec); the **inspector** opens as a sheet when an element is selected (tabs and groups as in 9.8 with large controls); the canvas fills the width with 8 px margins and the device switcher moves into the More sheet; the element toolbar docks at the bottom above the bar; drag uses long-press handles; a one-time InfoBox "The editor works best on a larger screen. You can still do everything here." Preview mode and the AI button work the same.
### 9.16 Accessibility and performance of the editor
All panels are landmarks with labels; the canvas iframe has a title and a live region announces selection changes ("Selected: Heading, level 2, in Hero section"); every control is keyboard reachable and labelled; the Layers tree follows the ARIA tree pattern; colour is never the only signal (chips have text and icons); focus indicators follow the global ring; reduced motion respected; targets as defined above. Performance: typing latency under 16 ms on a 500-node page, drag at 60 frames per second on 1,000 nodes, inspector updates apply to the canvas within 50 ms, style compile for one node under 2 ms and for the page under 60 ms, initial editor load under 3 seconds on a mid-range laptop (code-split Tiptap, CodeMirror, the patterns catalogue and the AI panels), memory stable over a 30-minute editing session (no leaks), the Layers tree virtualised.

## 10. AI inside the editor
### 10.1 Principles
AI proposes **edit patches** (Section 10.2) that are validated by the same code as manual edits (sanitisers, compiler, lint, plugin gating, limits), **previewed on the canvas** before they apply, applied as **one undo step**, and logged. AI reads only the capability map (8.2), the selected subtree, the page outline, the theme, the Design Spec and the brand voice and facts. It never writes scripts, never uses external URLs or fonts outside the catalogue, never creates elements that need a plugin that is off, never hides or alters the platform badge, never invents facts, and never creates letter-mark logos. Credits are shown first, reserved, settled and refunded as designed; all calls go through the resource governor (pools `ai_text`).
### 10.2 Edit patch format
```
EditPatch { version: 1, summary: string, ops: Op[], notes: Note[], unsupported?: string[] }
Op = insertNode { parentId, index, node } | updateProps { id, props } | updateStyle { id, device, state, set?: StyleDecl, unset?: string[] }
   | setAttrs { id, attrs } | setCss { id|'page'|'site', css } | moveNode { id, parentId, index } | removeNode { id }
   | replaceSubtree { id, node } | updateRichText { id, doc } | setHidden { id, hidden }
```
Limits: at most 150 ops per patch, 120 inserted nodes for a page, 40 for a section; nodes use only registry ids from the capability map; styles only whitelisted properties; custom CSS at most 2 KB per patch unless the user asked for custom CSS (then 6 KB); `unsupported` lists requests that could not be done with the nearest alternative. The server **applies the patch to a copy**, runs validation, lint and the accuracy verifier, repairs once or twice (as designed), then returns the preview tree and a human-readable change list.
### 10.3 "Generate page with AI" (top bar button, empty-state button, insertion-point menu)
- **Dialog** (720 wide, full-screen sheet below 768; steps in one scrollable form with a sticky footer): H2 "Generate a page with AI". **Step "What should this page show?":** Textarea "Describe the page" (min 120, max 800, counter, placeholder "For example: A services page for my salon with a short intro, six services with prices, a gallery, opening hours and a booking button"); **page type chips** (Home, About, Services, Menu, Pricing, Products, Portfolio, Gallery, Contact, Questions, Landing page for an offer, Event, Other); **Include** chips (Hero, Services or products, Gallery, Testimonials, Pricing, Questions, Team, Opening hours, Map, Contact form, Call to action) and **Leave out** chips; **Look** controls reused from the design step (style chips, spacing, corners, hero choice) with the switch "Use my colours and fonts" (default on); **"How to use the result"** radio cards: "Add to this page" (inserts at the end or at the selected insertion point), "Replace this page" (shows the warning "We save a copy first"; creates a restore point), "Create a new page" (name and address fields; respects the page limit); **"Allowed ingredients"** panel (read-only summary from the capability map): chips of what AI may use ("Elements and sections", "Contact form (on)", "Booking button (link)") and **blocked items with the reason** ("Contact form is off. AI will use call and WhatsApp buttons instead." with a "Turn on Contact form" action that runs the enable flow and refreshes the map); a switch "Allow custom CSS for special effects" (default off; helper "AI may add a small amount of safe CSS. It never uses scripts."). `CreditChip` ("About {n} credits") and the balance; language note for non-English sites. Buttons "Cancel" and "Generate" (primary-accent).
- **Progress:** `AiProgress` steps ("Understanding your request", "Choosing sections", "Building the layout", "Writing the text", "Checking the design", "Making it fit phones and tablets"); busy-time queue notice when applicable.
- **Result preview:** the dialog switches to a **live preview** (the generated tree rendered in a canvas at Desktop and Phone, tabs for the two sizes), a **change list** ("Added 7 sections: Hero, Services (6 items), Gallery..."), **notes** ("Contact form was not used because the plugin is off", "You asked for a video background. Applying inserts the nodes, selects the first, scrolls to it, shows a toast with "Undo", and adds a **review list** (sample content, claims to check) to the Tips tab.
- **Pipeline (`editor.page.generate`):** (1) **interpret** (design spec parse for the page: required sections, exclusions, tone, look; reuse the deterministic parsers and the verifier); (2) **plan** a section list from patterns first (**template-first**: choose patterns whose category, tags and business type match, using the capability map; fill remaining needs with primitive layouts), respecting the page and node limits; (3) **compose** (the model outputs the `EditPatch` for the chosen patterns with copied trees and text slots, plus custom compositions for anything not covered, using only registry ids, theme tokens and the layout recipes from the skill packs); (4) **write** (copy for each text slot using the existing writing rules and fact guard; sensitive blocks stay sample); (5) **responsive pass** (ensure tablet and phone overrides exist for rows, grids, large type and paddings; deterministic rules first: stack rows at phone, reduce display sizes, reduce section padding, full-width buttons; model only for exceptions); (6) **verify and repair** (sanitiser, compiler, lint (Section 12), plugin gating, accessibility rules, accuracy verifier; up to two repair rounds; failure falls back to a pattern-only page and says so).
- **Plugin and capability rules in the pipeline:** elements and sections that require a plugin appear in the plan **only if the plugin is on**; if the user's request needs one that is off, the result includes the nearest alternative and a note with an "Enable" action; custom CSS and `html` nodes are used **only when** the capability map allows custom code, the plan limits have room and the user allowed it (switch) or the request explicitly asks for something only code can do ("a diagonal divider", "glass effect").

### 10.5 Prompts, skills and verification
- Platform rules additions: use only registry ids and whitelisted style properties; express colours as theme tokens unless the user gave an exact colour; never output raw CSS unless a custom CSS task allows it; never output scripts, event handlers or external URLs; never target or mention the platform badge; produce phone and tablet overrides for any multi-column layout; keep exactly one `h1` per page; keep heading order; provide alt text; use semantic tags; keep text within limits; follow the user's explicit requirements literally; report anything not possible in `unsupported`.
- **Task prompts** (versioned `editor.page.generate@1`, `editor.section.generate@1`, `editor.style.patch@1`, `editor.responsive@1`, `editor.layout.fix@1`, `editor.css.write@1`, `editor.transform@1`) include the compressed registry (ids, one-line meanings, synonyms), the style property whitelist with value formats, the capability map, the page outline, the selected subtree (trimmed), the theme summary, the layout recipes, and at least **10 golden examples per task** (thin requests, plugin-off cases, long requests, adversarial requests such as "hide the Get-On badge", "add a script", "use this external font", "make a login form"); temperatures: patches 0.2, copy 0.6, CSS 0.2.
- **Skill packs (seed real content, within limits):** `design/editor-layouts` (how to compose rows, grids, cards, heroes, pricing tables, galleries and forms from primitives with responsive rules), `design/editor-style-vocabulary` (words to style properties: "soft shadow", "glass", "pill button", "tight", "airy", "bold headline"), `design/css-safe-effects` (what safe custom CSS can do and examples), `design/responsive-rules` (stacking, sizes, spacing scales), `design/pattern-selection` (choosing patterns by business type and goal), `task/editor-*` packs per task. The skill linter blocks packs that instruct the model to output scripts, external URLs or unlisted properties.
- **Verification:** every patch passes `validateContentV5`, the style compiler, the CSS sandbox, plugin gating, the layout and style lint, the accessibility rules and the accuracy verifier; hard failures trigger repair; unresolved items fall back to safe defaults and are reported to the user.
### 10.6 AI quality gates (CI with the fake provider; manual benchmark with real models)
At least **150 page requests** across 10 business types with plugin states (Contact on and off), languages, thin and long inputs, adversarial requests; targets: **100 percent** of results valid after repair (no sanitiser errors, no forbidden properties, no blocked plugin elements, no badge targeting), **zero** layout lint errors, responsive overrides present for **100 percent** of multi-column layouts, weighted request accuracy at least **90 percent** on supported requirements, diversity (no more than 15 percent of results share the same section sequence for the same request class). The admin AI Evals page includes the editor tasks.

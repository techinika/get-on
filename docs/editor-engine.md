# Editor engine specification (v5)

> The editor is replaced by `docs/ui-spec-editor-v3.md`. Where they conflict, v3 wins.

This document records the model, style system, safety, renderer/publisher contract and catalogue for schema version 5. It is normative. The core rules below apply to every package.

## 3. Core rules (write them into `docs/editor-engine.md` and `CLAUDE.md`; test each)
1. **One renderer, one CSS compiler.** The canvas (edit and preview modes), the published page, Website ZIP export, template previews and thumbnails all render from the same renderer and the same style compiler. The editor adds only overlay attributes and overlays; it never changes the structure of the output.
2. **Styles are structured data, compiled to CSS.** Visual controls write a validated style object; only the compiler produces CSS. Raw CSS exists only as sandboxed custom CSS (Section 6).
3. **Everything the user types is sanitised on the server** before it is saved or published: tree, styles, attributes, rich text, HTML, CSS. The client check is a convenience.
4. **No scripts, ever.** No `<script>`, no inline event handlers, no `javascript:` URLs, no iframes or objects, no external stylesheets or fonts, no external images from CSS.
5. **The Free-plan badge and "Report this site" link cannot be hidden, moved or restyled** by any user CSS, HTML, class or ID (Section 6.5), proven in a real browser.
6. **Plugin gating is part of the model.** Elements that need a plugin are marked; when the plugin is off they render nothing on the published site, show a clear "plugin is off" state in the editor, and are never created by AI.
7. **Every editor change is undoable** in one history, including style, structure, text, AI patches and custom CSS; autosave, versions and conflict handling continue to work.
8. **Responsive by construction:** desktop styles are the base; tablet and phone overrides are explicit and visible; AI and patterns always provide sensible overrides for multi-column layouts.
9. **Accessible output:** semantic tags, one `h1` rule, heading order, alt text, focus styles, contrast checks, tap targets; the layout lint and page tips run on trees.
10. **Performance budgets are enforced** for the editor and for published pages (Section 13).

## 4. Content model (schema version 5, `packages/blocks`)
### 4.1 Document
```
PageContentV5 {
  schemaVersion: 5
  root: Node                         // type 'page'; children are top-level nodes (sections and others)
  css?: string                       // page custom CSS, sandboxed (max 20 KB)
  meta?: { editorVersion: string }
}
Node {
  id: string                         // nanoid(10), unique per document
  type: NodeType
  name?: string                      // layer name (max 40)
  props: object                      // validated per type
  style?: StyleSet                   // structured styles (Section 5)
  attrs?: { id?: string, classes?: string[], aria?: { label?: string, hidden?: boolean }, data?: Record<string,string>, title?: string, tag?: string }
  css?: string                       // element custom CSS (max 4 KB)
  locked?: boolean
  hidden?: { desktop?: boolean, tablet?: boolean, phone?: boolean, all?: boolean }
  children?: Node[]
}
```
Limits: 2,000 nodes per page, depth at most 12, document at most 1 MB, text per node at most 20,000 characters, classes at most 10 per node, data attributes at most 10, `html` nodes at most 10 per page.
### 4.2 Node types (registry in `packages/editor-registry`)
**Layout:** `section` (semantic wrapper with width, padding and background defaults from the theme; tag choice `section`, `header`, `footer`, `main`, `aside`, `nav`, `article`, `div`), `container` (a group: tag choice `div`, `section`, `article`, `aside`, `header`, `footer`, `nav`, `figure`), `row` (flex row for columns; props `columns` preset, `gap`, `stackAt` (`tablet`, `phone`, `never`), `verticalAlign`), `column` (child of row; prop `span` 1 to 12 or `auto`), `grid` (CSS grid with props `columns` (1 to 12 or auto-fit with a minimum width), `rows`, `gap`), `stack` (vertical flex with gap), `card` (container preset with theme card styles).
**Text:** `heading` (levels 1 to 6, rich text), `paragraph` (rich text), `list` (ordered or unordered, items are rich text), `quote` (rich text with citation), `code` (display-only monospace text), `table` (simple, header row, up to 12 columns and 50 rows, rich text cells).
**Media:** `image` (media id, alt, caption, link, `fit`, ratio), `gallery` (grid of images with the existing zoom behaviour), `icon` (curated catalogue), `video-link` (the existing link card), `file-download` (PDF card), `map-card` (existing).
**Actions:** `button` (label rich-lite, link, variant), `buttons` (group), `link-list` (existing).
**Interactive without JavaScript:** `accordion` (group of `accordion-item` using `details`).
**Utility:** `divider`, `spacer`, `html` (sanitised static HTML, Section 6.3).
**Smart sections (the v4 blocks, kept as components):** `smart` nodes with `props.kind` = every v4 block type (hero, image-text, features, services, products, menu, pricing, projects, testimonials, team, stats, logos, steps, faq, quote, opening-hours, map, contact-details, contact-form, quick-contact, social-links, cta, link-list, button, downloads, gallery, before-after, video, spacer, divider) with their existing props and renderers; each also accepts the generic `style`, `attrs` and `css` of a node so the Style, Advanced and Settings tabs work on them. Smart sections bound to site data or plugins (`contact-form`, `quick-contact`, `contact-details`, `opening-hours`, `map`, `social-links`, `products` order buttons, `shared`) **cannot be exploded**; others can (Section 8.3).
**Dynamic inline node (inside rich text and props):** `field` with `key` in `business.name`, `business.tagline`, `business.phone`, `business.email`, `business.address`, `business.city`, `business.hoursSummary`, `site.address`, `year`; resolved at render time from the website settings; props `fallback` (plain text, brand-neutral) and `hideIfEmpty` (hide the whole parent element when empty). Replaces the earlier apply-time `{{ }}` variables (Section 4.9).
**Components that are not nodes:** header and footer (Section 9.12), shared and pattern references (`reference` node: `{ patternId, mode: 'synced' }`).
### 4.3 Rich text (extended)
Document nodes: paragraph, heading (inside text nodes), bullet list, ordered list, list item, blockquote, hard break, `field`. Marks: bold, italic, underline, strike, code, subscript, superscript, link (page, section anchor, URL https, tel, mailto, WhatsApp), **text colour** (token or hex), **highlight** (token or hex), `smallCaps`. No font-size or font-family marks (use element styles). Validation and sanitising: allow-list schema, link rules from `LinkTarget`, colours validated, maximum nesting 6, no raw HTML.
### 4.4 Attributes
- `attrs.id`: `^[A-Za-z][A-Za-z0-9_-]{0,63}$`, unique per page, **case-insensitive**, reserved prefixes forbidden (`gs-`, `ed-`, `zoom-`, `cookie`, `_`), reserved words (`top`, `main-content`, `skip`), also used for in-page links and shown in the section link picker.
- `attrs.classes[]`: each `^[a-z_][a-z0-9_-]{0,39}$` (lower case), reserved prefixes forbidden (`gs-`, `ed-`, `wp-`? no: only `gs-`, `ed-`, `is-`? keep `gs-`, `ed-`), duplicates removed, 10 maximum; style presets add classes starting with `p-` (system managed).
- `attrs.aria.label` (max 120), `attrs.title` (max 120), `attrs.data` keys `^data-[a-z][a-z0-9-]{0,30}$`, values max 120 (printable).
- `attrs.tag` is allowed only for node types that offer a tag choice and only from the type's allow-list.
### 4.5 Links
Existing `LinkTarget` plus `section`, `pageSection`, `file`, and **dynamic links** (`business.phone` as `tel:`, `business.email` as `mailto:`, WhatsApp from phone). External links get `rel="noopener noreferrer"` and open in a new tab when `newTab` is true.
### 4.6 Site-level and page-level data
- `project_settings`: add `custom_css text not null default ''` (site CSS, max 20 KB on Free, 50 KB on paid plans; proposed, plans column `custom_css_kb`), `style_presets jsonb not null default '[]'` (max 100: `{ id, slug, name, style, createdBy }`), `editor_header_tree jsonb null`, `editor_footer_tree jsonb null` (optional trees for header and footer, Section 9.12).
- `pages.content` carries `PageContentV5` (the page `css` lives inside it).
- `profiles.editor_prefs jsonb default '{}'` (Section 9.14).
- `patterns` table (Section 8.4).
### 4.7 Validation, normalisation and limits (`validateContentV5`)
One function used by the editor (fast path), the save RPC (authoritative), the publisher, the importer and the AI verifier: validates structure and props per type, enforces limits, normalises ids (regenerates duplicates), compiles and validates styles (Section 5), sanitises rich text, HTML and CSS (Section 6), checks plugin requirements (marks nodes), returns `{ ok, content, warnings, errors }`. Unknown node types are dropped with a warning (never crash); errors block saving only when security-relevant (the sanitiser removes the unsafe part and records a warning instead of failing whenever possible).
### 4.8 Revisions, size and plan limits
`save_page_content` accepts schema 5, runs the authoritative validation server-side (in the application layer before the RPC), enforces the 1 MB limit, the 2,000 node limit and the plan limits for custom code size, keeps revision checks, autosnapshots and conflict handling as built. Page limits and plugin rules are unchanged.
### 4.9 Migration (v4 to v5; v4 pages keep rendering until converted)
- **Converter** `migrateV4ToV5(content)`: root `page` node; each v4 block becomes a top-level `smart` node (`kind` = old type, `props` = old props minus `sec`); `sec` maps to node `style` and `attrs`: background types to background styles (`plain` none, `soft` and `brand` and `accent` to theme token references, `color` to colour, `gradient` to gradient, `image` to image with overlay), spacing to padding top and bottom tokens, width to max-width, `anchor` to `attrs.id` (valid and unique; otherwise suffixed), `menuLabel` kept in `props`, `hideOn` to `hidden`, `hidden` to `hidden.all`, shapes and patterns to the corresponding style properties; `shared` blocks to `reference` nodes; v4 plugin blocks keep their `requiresPlugin` mapping.
- **Parity requirement:** for every fixture, every system template page and every ready-made template, the v5 render equals the v4 render visually: pixel difference under **1 percent** at 390, 768 and 1280 widths (snapshot test; document the cases where an intentional difference exists).
- **When it runs:** lazily when a page is first opened in the new editor (creating a version `before_editor_v3` for rollback), by the template build script for all system templates, by AI and import code paths on read, and by an optional batch `pnpm migrate:editor-v5 --apply` (dry run by default, resumable, idempotent). The publisher and renderer support **both** versions until the batch has migrated everything and the old editor is removed.
- **Rollback:** restoring the `before_editor_v3` version returns the page to v4 content; the old editor stays reachable behind the flag for one release.
- **Templates:** template packages move to `packageVersion: 2` (v5 trees; compositions, header and footer trees optional, dynamic fields instead of variables); old packages migrate on read; the apply engine, content map, sample detection, quality gates and previews are updated to trees (map text slots by traversing nodes with `props.text` and rich text nodes, keep slot ids stable via node ids).

## 5. Style system (`packages/blocks/style`)
### 5.1 StyleSet
```
StyleSet {
  base: StyleDecl                      // desktop and all sizes (desktop-first)
  tablet?: StyleDecl                   // overrides at container width <= 899
  phone?: StyleDecl                    // overrides at container width <= 639 (inherits tablet overrides)
  states?: { hover?: StateStyles, focus?: StateStyles, active?: StateStyles }   // each StateStyles has base, tablet, phone
}
StyleDecl = { [property]: Value }       // only whitelisted properties, validated values (5.2)
```
`desktop-first`: tablet and phone declarations are emitted inside `@container site (max-width: 899px)` and `@container site (max-width: 639px)` blocks after the base so they override it. `.gs-root` is the named container (`container-name: site; container-type: inline-size`), so the canvas iframe at a given width and a real phone behave identically.
### 5.2 Property whitelist and value types (anything else is rejected)
| Group | Properties and structured values |
|---|---|
| Layout | `display` (`block`, `flex`, `grid`, `inline-flex`, `inline-block`, `inline`, `none`, `contents`), `flexDirection`, `flexWrap`, `justifyContent`, `alignItems`, `alignContent`, `alignSelf`, `justifySelf`, `gap`, `rowGap`, `columnGap`, `gridTemplateColumns` (structure: `{ mode: 'repeat', count, min? }`, `{ mode: 'autoFit', min }`, `{ mode: 'custom', tracks: [length or fr] }` up to 12 tracks), `gridTemplateRows` (same, up to 12), `gridColumn` and `gridRow` (span or line numbers), `gridAutoFlow`, `placeItems`, `order`, `flexGrow`, `flexShrink`, `flexBasis` |
| Size | `width`, `minWidth`, `maxWidth`, `height`, `minHeight`, `maxHeight`, `aspectRatio`, `overflowX`, `overflowY`, `objectFit`, `objectPosition`, `boxSizing` |
| Spacing | `margin{Top,Right,Bottom,Left}`, `padding{Top,Right,Bottom,Left}` |
| Position | `position` (`static`, `relative`, `absolute`, `sticky`; **`fixed` is not allowed**), `top`, `right`, `bottom`, `left`, `zIndex` (-10 to 100) |
| Typography | `fontFamily` (a catalogue font id or the tokens `heading` and `body`; never free text), `fontSize`, `fontWeight`, `fontStyle`, `lineHeight`, `letterSpacing`, `wordSpacing`, `textTransform`, `textAlign`, `textDecoration` (`{ line, style, color, thickness }`), `textIndent`, `whiteSpace`, `textWrap`, `textOverflow`, `hyphens`, `columnCount`, `columnGap`, `columnRule`, `textShadow` (structured layers), `color` |
| Background | `backgroundColor`, `backgroundImage` (structured: `{ type: 'media', mediaId, overlay? }` or `{ type: 'gradient', gradient }`; up to 3 layers), `backgroundSize`, `backgroundPosition` (percent pair or keywords; focal point from media), `backgroundRepeat`, `backgroundAttachment` (`scroll`, `fixed` is disabled on touch via media query), `backgroundBlendMode`, `backgroundClip` |
| Border | `border{Top,Right,Bottom,Left}` (`{ width, style, color }`), `borderRadius{TopLeft,TopRight,BottomRight,BottomLeft}`, `outline` (`{ width, style, color, offset }`) |
| Effects | `boxShadow` (structured layers up to 6: x, y, blur, spread, colour, inset), `opacity` (0 to 1), `filter` (structured: blur, brightness, contrast, grayscale, hueRotate, invert, saturate, sepia), `backdropFilter` (blur, saturate only), `mixBlendMode`, `clipPath` (presets: `slant`, `curve`, `circle`, `ellipse`, `polygon` with up to 12 points in percent), `cursor` (a short list: `auto`, `pointer`, `default`, `text`, `not-allowed`) |
| Transform and motion | `transform` (structured: translateX, translateY, rotate, scale, scaleX, scaleY, skewX, skewY; limits), `transformOrigin` (nine positions), `transition` (list of `{ property, duration 0 to 2s, delay 0 to 2s, easing preset }`, properties from a short list: `all`, `color`, `background-color`, `border-color`, `box-shadow`, `opacity`, `transform`), `willChange` is **not** allowed |
Values: lengths (`px`, `%`, `em`, `rem`, `vw`, `vh`, `svh`, `ch`, `fr` where relevant, `auto`, 0; magnitudes limited per property, for example `vh` heights at most 300), numbers with limits, keywords from allow-lists, **colours** as `{ token: 'primary'|'accent'|'bg'|'text'|'soft'|'card'|'border'|'muted'|'link'|'on-primary'|'on-accent' , alpha?: 0..1 }` or `{ hex: '#RRGGBB', alpha?: 0..1 }` (`rgb`, `hsl` converted on input; stored as token or hex so a future dark mode plugin can remap tokens), gradients as `{ type: 'linear'|'radial'|'conic', angle?, shape?, stops: [{ color, position 0..100 }] (2 to 6 stops) }`, spacing scale tokens (`0, 4, 8, 12, 16, 24, 32, 48, 64, 96, 128`) offered by the UI but any valid length allowed. `calc()`, `var()`, `min()`, `max()`, `clamp()` are allowed **only** through structured fields the compiler builds itself (for example fluid font size `{ mode: 'fluid', min, max }` compiles to `clamp()`); free text expressions are not accepted in structured styles.
### 5.3 Compiler (`compileStyles(nodes, theme) → { css, classMap }`)
- Each unique `StyleSet` is hashed (canonical JSON) and compiled once into a class `gs-s-{hash8}`; nodes reference the class (identical styles share one rule: dedupe). Per-node overrides that cannot be shared use `gs-n-{nodeId}`. Emit order: base, tablet, phone, then states (`:hover`, `:focus-visible`, `:active`, each with its own tablet and phone blocks); hover rules are wrapped in `@media (hover: hover)` so touch devices do not get sticky hover.
- Selectors never contain user input. Output is minified, deterministic and size-aware: a per-page `styleBudgetBytes` (gzipped 40 KB soft limit with a page tip; 120 KB hard limit at publish with a plain error).
- **Fonts:** every `fontFamily` reference is added to the page's font list so the publisher embeds the files (up to the existing font budget: two heading or body families from the theme plus **at most two more** families used by styles; exceeding the budget produces a warning and falls back to the theme fonts for the extra ones).
- **Backgrounds and media:** images are referenced by media id and resolved to the correct variant URLs at build time; no raw URLs.
- **Defaults and inheritance:** nodes without styles inherit from the theme tokens and the registry defaults (for example paragraph size `--s-body`, heading sizes from `--s-h1..h3`), so unstyled elements look right and respond to theme changes.
- A style **diff** utility computes the minimal changes (used by undo, AI patches and the "changed" indicators).
### 5.4 Style presets
Presets are named style sets stored per website (`style_presets`) and compiled as classes `p-{slug}`; applying a preset adds the class and the compiler emits the preset rule **before** the node's own styles so local edits override it; editing a preset updates every user. Operations: save current styles as preset, apply, detach (copy styles back to the node), rename, delete (detaches users first), import from the theme's button and card styles. Maximum 100 presets.
### 5.5 Responsive and state semantics
Editing at Desktop writes `base`; editing at Tablet or Phone writes only the differing properties into `tablet` or `phone`; resetting a property removes the override. The inspector shows an **override dot** beside every property that has a value at the current device and a lighter dot when inherited from a larger device; "Copy desktop to this device" and "Clear all overrides" are available per group.
### 5.6 Cascade layers (published CSS and canvas)
Output order: `@layer gs-protect, gs-base, gs-theme, gs-nodes, gs-user;`. Renderer and theme CSS live in `gs-base` and `gs-theme`; the compiled node styles in `gs-nodes`; **sanitised user CSS** (page, site and element custom CSS) in `gs-user` (so it can override node styles without specificity fights). The platform badge protections live in `gs-protect` **and** as inline `!important` styles on the badge elements (Section 6.5). The canvas uses the same layers inside its iframe. Verify the behaviour in Chromium, Firefox and WebKit (prototype task); provide the fallback that, where `@layer` is unsupported, the same CSS is emitted in the same order without layers and the badge inline protection still holds.

## 6. Safety: custom CSS, HTML and attributes
### 6.1 Custom CSS sandbox (`packages/blocks/css-sandbox`)
Parse with a robust CSS parser (postcss or lightningcss; verify licence), operate on the AST, **never** on strings. Scoping: every rule is rewritten so that it can only match inside the page: selectors are prefixed with `.gs-root` (site and page CSS) or with the element's own scope class `gs-n-{id}` (element CSS: the keyword `selector` is replaced by the scope class; other selectors are treated as descendants of it, for example `selector a` or `& .title`). Forbidden or rewritten:
- **At-rules:** allowed `@media` (viewport and container features), `@container`, `@supports`, `@keyframes` (names are prefixed `gsu-` and referenced animations are rewritten), `@layer` (flattened into `gs-user`); **forbidden** `@import`, `@font-face`, `@namespace`, `@charset`, `@page`, `@property`, `@counter-style`, `@font-feature-values`, `@font-palette-values`, `@view-transition`, `@scope`, `@starting-style`, `@document`, and unknown at-rules.
- **Selectors:** `html`, `body`, `:root`, `*` at the top level, `:host`, `::backdrop`, any selector that contains an id or class prefixed `gs-` or `ed-` **except** through the allowed scope classes, and any selector targeting the platform badge, report link, consent or analytics elements are removed with a warning. Complexity limits: selector length at most 200 characters, depth at most 8 compound selectors, at most 6 `:is()`, `:where()`, `:not()` and `:has()` combined per selector, **`:has()` allowed** but only with a simple argument (performance); at most 400 rules per site and 100 per element.
- **Declarations:** property allow-list is **wider** than structured styles but excludes dangerous ones (`behavior`, `-moz-binding`, `expression`, `-webkit-user-modify`, `-webkit-mask` loading external images, `content` with `url()`, `src`, `will-change`, `contain`? allowed, `position: fixed` allowed **only** when the same rule also sets `pointer-events: none` is **not** the rule; instead **`position: fixed` is rewritten to `position: sticky`** with a warning to prevent full-screen overlays). `url()` allowed only for `data:image/svg+xml` smaller than 4 KB (sanitised by removing scripts and external references), `data:image/png|jpeg|webp|gif` smaller than 8 KB, and relative asset paths `/assets/...` belonging to the site; everything else is removed. `image-set()` and `src()` with external sources removed. `font-family` values must be catalogue families (or generic families); unknown names are dropped.
- **Size and cost:** site CSS up to the plan limit, page CSS 20 KB, element CSS 4 KB; total rules and complexity budgets as above; animation count at most 10 `@keyframes` per site; `animation` declarations respect `prefers-reduced-motion` automatically by wrapping them in `@media (prefers-reduced-motion: no-preference)`.
- **Output:** the sanitiser returns `{ css, issues: [{ level, message, line, column, rule }] }`; issues appear inline in the editor and in the developer drawer; unsafe parts never reach the published page.
### 6.2 HTML sanitising (`html` element and any imported HTML)
Allow-list tags: `a, abbr, article, aside, b, blockquote, br, caption, cite, code, col, colgroup, dd, details, div, dl, dt, em, figcaption, figure, footer, h1, h2, h3, h4, h5, h6, header, hr, i, img, li, main, mark, nav, ol, p, pre, q, s, section, small, span, strong, sub, summary, sup, table, tbody, td, tfoot, th, thead, time, tr, u, ul`; allow-list attributes: `class` (validated), `id` (validated), `href` (https, tel, mailto, relative page links), `src` (relative media only), `alt`, `title`, `width`, `height`, `colspan`, `rowspan`, `scope`, `datetime`, `open`, `lang`, `dir`, `aria-*`, `role` (allow-listed), `data-*`; `style` attributes are **converted** into a scoped class by running them through the CSS sandbox. Forbidden: `script`, `iframe`, `object`, `embed`, `form`, `input`, `button` (use the Button element), `link`, `meta`, `base`, `style` tags, `svg` (use the icon catalogue), `video`, `audio`, `canvas`, event handler attributes, `srcdoc`, `javascript:` and `data:` URLs except images already allowed. `img` sources must be media of the site. Maximum 20 KB per `html` node, 10 nodes per page, nesting depth 12. The sanitiser runs server-side with a maintained library (verify) plus our own post-checks.
### 6.3 Attribute and ID safety
IDs and classes follow 4.4. A page publishes only if ids are unique after normalisation; duplicates are suffixed automatically in the editor and flagged in Page tips. Classes referenced by custom CSS but unused produce a tip.
### 6.4 Content screening
Extend the content screen (phishing, impersonation, crypto promises, shorteners) to scan `html` nodes, text produced by `content:` declarations in custom CSS, link targets and all rich text; flagged results follow the existing review and publish rules (`review_state`). Block known abuse patterns: look-alike login forms built from elements (inputs are not available), full-page overlays, hidden text (font-size 0, transparent text over a link) as warnings and flags; CSS that tries to hide or restyle the platform badge is **removed** and recorded in the security event log.
### 6.5 Platform badge protection (Free plan)
- The badge and "Report this site" link are rendered by the publisher **outside user content** (a footer region the user trees cannot contain), have **inline `!important` styles** for `display`, `visibility`, `opacity`, `position`, `font-size`, `width`, `height`, `max-height`, `overflow`, `clip-path`, `transform`, `filter`, `color`, `background`, `pointer-events` and `z-index`, are also protected in `@layer gs-protect`, and the parent footer region has the same protection. User CSS selectors that could match them are removed by the sandbox; a `body > *` style cannot reach them because the root scoping excludes the footer region. The publisher asserts at build time and a **browser test** asserts at runtime (computed styles, bounding box inside the viewport at the end of the page, not covered by another element with a higher z-index via `elementFromPoint`) for adversarial CSS and HTML fixtures (at least 60 attack cases, including huge z-index overlays, `margin-bottom` negative values pulling the footer under content, `overflow: hidden` on parents, `clip`, `text-indent`, `::after` covers, and `content: ''`).
- Paid plans may remove the badge only through the existing plan flag (never through CSS).
### 6.6 Abuse limits and logs
Custom code size and complexity limits per plan (`plans.custom_css_kb` Free 10, Basic 30, Pro 50, Enterprise 100; `html` nodes per page Free 3, paid 10; proposed). Every save that changes custom CSS or HTML records a team activity event `custom_code_changed` (counts and byte sizes only, never the code) for owners and admins; the publish preflight lists custom code sizes and warnings; admins (staff) never see the code.

## 7. Renderer and publisher integration
- **Renderer v5:** a pure server-renderable function renders nodes to HTML with semantic tags, classes `gs-el gs-t-{type}`, the compiled style classes, `attrs`, anchors, `data-gs-node` attributes **only when `mode: 'edit'`**, dynamic fields resolved from the profile, plugin-off nodes omitted, hidden-device nodes handled with container-query classes, images from media variants (existing rules), links resolved with `primaryUrl`, rich text to HTML through the allow-list. Smart sections render through the existing block renderers with the generic wrapper (classes and styles) applied.
- **CSS:** `renderCss` (single manifest) gains the element CSS parts (one file per node type and per smart section variant), the compiled node and user layers, layered output (5.6) and keeps `assertStyled` (the published CSS gate) extended with: layer declarations present, node classes referenced by the HTML exist in the CSS, user CSS only inside `gs-user`, protective rules present, no `@import`, no external URLs, total size within budgets.
- **Publisher:** builds from v4 or v5 pages; compiles styles per page; embeds fonts used by styles; resolves media; enforces plan limits (pages, plugins, custom code sizes); writes the source snapshot as before; Website ZIP export uses the same path with portability checks (no custom code referencing platform features); sitemap and SEO unchanged; the preflight adds style budget, custom code summary, duplicated ids, missing alt text, heading order and tap-target warnings.
- **Parity:** the same function renders the canvas in edit mode, the preview mode and the published page; tests compare DOM and computed styles between preview mode and the published output for fixtures at 390, 768 and 1280.
- **Editor-only rendering extras (edit mode):** empty containers show a dashed placeholder through editor CSS (never in published output); plugin-off nodes show a ghost card; hidden-on-device nodes are drawn at 35 percent opacity with a hatch; locked nodes show a small lock; none of this changes layout metrics.

## 8. Catalogue: elements, smart sections, patterns, plugins
### 8.1 Registry contract (`packages/editor-registry`)
Every element, smart section and pattern is registered with: `id`, `label`, `description`, `category`, `keywords` and synonyms (search), `icon`, `requiresPlugin?`, `allowedParents`, `allowedChildren`, `defaults` (props and style, using theme tokens), `settingsPanel` (the Settings tab fields), `styleCapabilities` (which style groups apply), `render`, `toolbar` actions, `aiHints` (when to use, limits, examples) and `previewData`. **Plugins register their own elements, smart sections and patterns** through the same API (the Contact plugin registers `contact-form`, `quick-contact`; future plugins register theirs); a plugin's elements are listed under "Plugins" in the Add panel with their on or off state.
### 8.2 Capability map (`getCapabilities(projectId)`)
Returns for the current website: `elements` (allowed ids), `smartSections` (allowed ids with limits), `blocked` (`[{ id, reason: 'plugin_off'|'plan'|'limit', pluginId?, enableHint }]`), `patterns` (ids with availability), `limits` (pages left, nodes, custom code sizes, html nodes), `customCode` (`css: boolean, html: boolean, remainingBytes`), `theme` summary (palette tokens, fonts), `language`, `businessType`. The editor, the Add panel and **all AI tasks** read this single source, so a disabled plugin can never be used by the editor UI or by AI.
### 8.3 Convert to editable layout
"Convert to elements" (block menu and Settings tab) explodes a smart section into primitive nodes that render **identically** (parity under 2 percent pixel difference at 390, 768 and 1280): required for `hero` (all ten layouts), `heading`, `text`, `image`, `image-text` (all variants), `features` (all variants), `services` (cards, list, columns with rules), `cta` (strip, card, banner, split, ribbon), `stats`, `steps`, `faq`, `testimonials`, `logos`, `team`, `gallery` (grid and mosaic), `quote`, `link-list`, `products` (grid, catalog, lookbook), `pricing`, `projects` (grid and list), `button`. Not convertible (data or plugin bound, labelled "Connected section" with a lock and the reason): `contact-form`, `quick-contact`, `contact-details`, `opening-hours`, `map`, `social-links`, `shared`, `downloads`, `menu` (keeps its structured editor), `before-after`, `video`. Conversion is one undo step; a "Convert back" is not provided (undo only).
### 8.4 Patterns (template sections) and saved sections
- **System patterns:** `pnpm build:patterns` generates patterns from every section of every system template composition and from every block variant, converts them to v5 trees, tags them (category, style: light, dark, minimal, bold; business types; hero layout ids), renders thumbnails with the site's own theme at insertion time (live previews) and with default themes for the catalogue. Minimum **120 patterns** across: Hero (20), Features (12), About and story (10), Services (10), Products (8), Portfolio and projects (10), Testimonials (8), Pricing (6), FAQ (6), Call to action (10), Team (6), Contact (8), Gallery (6), Stats (4), Logos (3), Steps (5), Footer sections (4). Each pattern uses **theme tokens only** for colours and fonts (so it adapts to the website), passes the layout lint, contrast checks and responsive screenshots at 390, 768 and 1280 with zero horizontal overflow, includes tablet and phone overrides, has neutral sample text (flagged as sample), uses no letter marks, and marks plugin-dependent parts with `requiresPlugin` and a fallback.
- **Saved patterns:** `patterns` table (`id`, `team_id` null for system, `scope` (`team`), `name` (max 60), `category`, `tags[]`, `tree jsonb`, `thumbnail_key`, `mode` (`copy`, `synced`), `version`, `created_by`, `created_at`, `updated_at`); "Save as pattern" from any selection (single node or several siblings) with a name, category and tags (AI can suggest); **synced** patterns are `reference` nodes whose edits change every use (the earlier shared sections are migrated into synced patterns); detaching converts a reference into a normal subtree. Limits per team by plan (Free 5, Basic 20, Pro 50, Enterprise 200). RLS and permissions as for page editing; patterns can be used across all websites of the team.
- **Template sections in the panel:** the Add panel lists patterns with live previews using the current website theme, filters (category chips, style chips, "For my business type" toggle, search with synonyms), and shows plugin-dependent ones with the on or off state.

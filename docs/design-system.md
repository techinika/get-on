## 6. Design system extension (renderer contract)
**Principle:** variety must come from **structure** (layout, alignment, rhythm, scale, shape, texture, colour), not only palette. All additions are **optional and additive**: old content, old themes and old templates keep rendering exactly as before (defaults reproduce today's look). `schemaVersion` stays 4; schemas, migrations (map old hero layouts), the design catalogue and docs are updated. All colours still come from `--s-*` and `--sec-*` tokens (no new hex in renderer code). Every addition is CSS-only (no client JavaScript), uses container queries (`sm` below 640, `md` 640 to 899, `lg` 900 and above), and must be tested at 390, 768 and 1280.

### 6.1 Theme design options (`theme.design`, optional object; defaults in brackets)
| Option | Values | Effect |
|---|---|---|
| `headingCase` [`normal`] | `normal`, `upper` | `text-transform` for H1 and H2 (and wordmark when `wordmark.case` unset) |
| `headingTracking` [`normal`] | `tight` (-0.03em), `normal` (-0.01em), `wide` (0.06em) | letter-spacing of headings |
| `display` [`normal`] | `normal`, `dramatic` | hero heading size: normal uses `--s-h1`; dramatic uses `--s-display`: sm 44, md 64, lg 88 px, line-height 1.02, tracking -0.03em |
| `rhythm` [`even`] | `even`, `alternate`, `tinted`, `bold` | automatic section backgrounds when a block's `sec.bg` is `plain`: even (all plain), alternate (every second section `soft`), tinted (soft, plain, soft with a 1px rule), bold (alternate between `soft` and a **strong** section using `--s-primary` or `--s-text` with on-colour text, at most one strong section per 3 sections, never two adjacent, never the first) |
| `imageStyle` [`rounded`] | `rounded`, `sharp`, `arch`, `offset`, `circle` | default treatment of `image`, `image-text`, `team`, hero images (arch: radius `999px 999px var(--s-radius-lg) var(--s-radius-lg)`; offset: frame described in 6.5 layout `offset-frame`; circle only for avatars and team) |

Tests assert defaults equal the previous rendering (snapshot parity).

### 6.2 Type and spacing tokens (additions)
`--s-display` (above), `--s-hero-pad-y` by density (sm / md / lg): compact 56 / 80 / 96; comfortable 72 / 104 / 136; airy 96 / 136 / 184; `--s-measure: 62ch`; `--s-gutter` 20 / 32 / 48; `--s-eyebrow-gap` 16; `--s-title-gap` 12 (space between heading and intro); `--s-stack` 28 (space between paragraphs and buttons). `--s-pad-y` keeps its earlier values. Section spacing options (`sec.spaceTop`, `sec.spaceBottom`) multiply `--s-pad-y` as before.

If the owner uploaded a logo **image**, it replaces the wordmark; otherwise only the text is shown.

### 6.4 Footer layouts (`footer.layout`; add `bigbrand`)
`bigbrand`: top area grid at `md`+ (`1.2fr 1fr 1fr 1fr`, gap 48, padding 72 0 40): about text (15/1.6 muted max-width 320), up to three link columns; below it a **giant wordmark** (the business name, heading font weight 800 at `clamp(56px, 14cqw, 200px)`, line-height 0.85, tracking -0.04em, colour `color-mix(in srgb, var(--s-text) 10%, transparent)` or on dark `rgba(255,255,255,0.12)`, `overflow: hidden`, `white-space: nowrap`, margin-top 24); bottom legal row (13 muted, 1px top rule, padding-top 20). Other layouts unchanged. Footers never show an icon mark before the name.

### 6.5 Section extras (`sec.shape`, `sec.pattern`, `sec.rule`, added to every block's `sec`)
- `shape.top` and `shape.bottom` [`none`]: `slant` (clip-path polygon cutting `clamp(24px, 4cqw, 64px)` diagonally), `curve` (bottom or top edge a shallow elliptical arc using `clip-path: ellipse(…)` or a border-radius of 50% / 40 px), `wave` (an inline SVG mask, one sine wave 48 px high). The neighbouring sections' backgrounds show through (use negative margin of the same height so no gaps). Not allowed on the first or last section of a page.
- `pattern` [`none`]: `dots` (radial-gradient dots 1.5 px every 20 px at 14 percent of `--sec-text`), `grid` (1px lines every 48 px at 7 percent), `lines` (45 degree 1px lines every 14 px at 6 percent), `noise` (inline SVG turbulence data URI at 6 percent opacity). Only on `plain`, `soft`, `brand`, `accent` backgrounds.
- `rule` [`none`]: `top`, `bottom` (hairline or bold per `theme.design.rules`).
All three must respect contrast (patterns never drop text contrast under AA; tested).

### 6.6 Wordmark rule (applies everywhere: renderer, templates, AI, previews)
**Never render an icon, monogram or tile made from a letter or character before or instead of a business name** (no "first letter in a rounded square", no emoji). The name is plain typographic text styled by `theme.design.wordmark`. The only allowed image is an owner-uploaded logo file. Audit and remove: the renderer header and footer, template packages, ready-made section templates, generated platform pages, AI outputs and the AI design step (it must not offer logos), published social images, preview thumbnails inside the dashboard that imitate sites (use real render screenshots instead). The **favicon** fallback (a letter icon used only as the browser tab icon when no logo exists) is kept and is never shown inside pages; the Page tips panel gets a tip "Add a logo for your browser tab" when the favicon is the letter fallback. Add a test that fails if any rendered site HTML contains a first-letter tile before the wordmark.

### 6.9 Design catalogue (`packages/blocks/design-catalogue.ts`, single source for the editor, the parsers, the AI prompts and the verifier)
Exports typed lists with `id`, `label`, `description`, `whenToUse`, `avoidWhen`, `synonyms[]` (words users say, for example hero `split` has "split screen", "half and half", "image on one side"; `editorial` has "magazine", "big type", "poster"; `fullbleed` has "full screen photo", "background image"; `arch` has "arched image", "rounded top"; `product-shot` has "app mockup", "dashboard screenshot", "browser window"; `diagonal` has "slanted", "angled"; `card-over-image` has "text box over photo"), for: hero layouts, header styles, footer layouts, block variants, `theme.design` options, section shapes and patterns, rhythm, density, corners, buttons, fonts (curated pairs with feels), palette presets (with moods and synonyms), archetypes (the 10 templates). A build script validates every id against the schemas and CSS manifest.
